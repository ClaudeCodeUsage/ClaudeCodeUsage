## 本轮生产变更

### 1. Codex 一次性回填真正使用本机性能

- `codexIndexWorker` 只在首次或未完成回填时创建本地 file-pass pool；worker 数为
  逻辑 CPU 的一半，上限 6。本机 16 逻辑 CPU 因此使用 6 个 worker。
- main、lineage、period、identity 四类相互独立的 per-file pass 可并行执行；结果仍按
  原顺序提交，串行路径与并行路径的完整索引有 deep-equality 回归测试。
- JSONL 流 chunk 从小块提高为 1 MiB；Codex 单行安全上限仍为 1 MiB。Claude 复用同一
  scanner 时明确传入无穷单行上限，保留其既有超大首条记录语义。
- 实时 UI progress 仍频繁更新；大型持久索引约每 10 秒、2 GiB 或 256 个完成 pass
  保存一次，并在阶段边界保存。这样保留取消、崩溃恢复和原子续建，同时避免数十 MB
  索引文件反复写盘主导回填耗时。
- 小型 warm append 只做一次 durable checkpoint；worker 已经由最终 checkpoint 保存时，
  不再重复做第二次 final save。
- 全局 lineage 只在可能改变它的阶段 reconcile；lineage/period 等后续阶段复用已验证
  关系，不再对同一大索引重复执行多轮全局核对。
- 回填完成后 pool 被销毁；正常自动刷新恢复到 64 pass / 128 MiB 的低功耗预算，
  手动刷新仍是 512 pass / 2 GiB。无变化 refresh 不读 usage JSONL body，也不写索引。

### 2. “歧义”不再伪装成“仍在索引”

- base 与所需 period coverage 完成后，重复 session 的稳定身份歧义只显示为
  `ambiguous-session-identity` 数据质量说明。
- 两份无法证明相同的本地副本继续全部保留，不做猜测性去重；但它们不会让页面永久显示
  「索引仍在进行」。这只改变终态表达，不改变 Token 总量。

### 3. Claude #87 进入正式运行路径

- `claudeIncrementalIndex.ts` 现在是 Extension Host 内 Claude 用量刷新的生产路径。
- 每个文件保留内存 contribution、已验证 offset 与 tail signature；append 只读 tail，
  truncate、replace、move、delete 只处理受影响文件。
- Cross-file response identity、同 message 的 request-ID cardinality、缺失 request-ID 回退、
  prompt retry、content UUID 首 owner、title、context、session/project/branch/workflow、
  costliest message 与时段 bucket 均通过增量更新保持旧 full-loader 的精确结果。
- Dashboard 常用 aggregate 和 row 已物化；一个文件变化不会再对全部 records 重跑所有
  聚合。诊断新增匿名 `bodyReads` 与 `aggregateMutations`，不记录路径、ID 或正文。
- 索引目前仅驻留内存：新的 Extension Host 会执行一次 cold build；同一运行期的 watcher
  事件和刷新走增量路径。这正面解决 #87 的“每次 changed-file 都重读全语料”，但没有在
  V2.3.0 新增第二份 Claude 持久索引文件。

## 统计与隐私不变量

- Codex valid `last_token_usage` 仍提供精确 request component；其 `total_tokens` 仍是
  active context，不是 request 用量。缺失 last snapshot 时才使用 cumulative high-water。
- Cached input 仍是 input 子集，reasoning 仍是 output 子集，均不重复计费或重复计入
  processed。
- API 等效成本只对已知模型按当前官方 API Token 单价计算；未知模型不定价，结果不是
  账单或订阅扣费。
- Codex raw ID/path 只存在于短期本地 worker memory；持久化仍只有 machine-salted key、
  数字与白名单结构 metadata。没有读取 credential、SQLite、prompt、response、command
  或 tool argument。
- Claude JSONL 保持只读；增量索引不新增磁盘持久化，不新增 runtime dependency。

## 已知且接受的边界

- Claude per-file index 在 V2.3.0 为内存索引，Extension Host restart 后会 cold build 一次。
- Codex `session_index.jsonl` 的安全 title mapping 仍会单独流式读取，不属于 usage JSONL
  zero-body-read 承诺。
- Codex 稳定身份歧义会保留双方并显示质量 warning；它不再显示为活动索引任务。
- 订阅档位（20/100/200 美元）仍未自动归属账号。本地日志缺少可靠 account + plan identity；
  后续只能采用用户明确 opt-in 的账号映射，不能猜测。
- Provider-specific 视觉风格适配继续留给后续版本；本次保持共享 dashboard 设计系统。
