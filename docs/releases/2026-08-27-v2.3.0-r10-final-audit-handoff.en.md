## Decision summary

This follow-up fixes the real 20-GB-class Codex experience that could remain in
an indexing state for hours, and promotes the #87 Claude changed-file prototype
into the production refresh path. It does not redefine Claude or Codex token,
cache, reasoning, request-replay, active/archive deduplication, or lineage
ownership semantics. It computes the same semantics with less repeated parsing,
global reconciliation, aggregation, and index persistence.

After the final gates and installed VSIX check recorded below, Claude should
perform one read-only final audit. If it finds no new P0/P1 issue, PR #93 is ready
for the maintainer's merge decision. The audit must not merge, tag, or publish.

## Production changes

### Codex backfill throughput

- First or incomplete backfills use an adaptive local file-pass pool: half the
  logical CPUs, capped at six workers. A 16-logical-CPU Mac uses six workers.
- Independent main, lineage, period, and identity file passes run concurrently;
  outcomes are applied in stable order. Regression coverage deep-compares the
  complete parallel and sequential indexes.
- JSONL stream chunks are 1 MiB. The Codex line safety limit remains 1 MiB;
  Claude explicitly uses an unlimited line length when reusing the scanner.
- UI progress stays frequent. Large durable snapshots are saved at roughly
  10 seconds, 2 GiB, or 256 completed passes, plus stage boundaries. Cancellation,
  atomic resume, and crash recovery remain bounded without making repeated
  tens-of-megabytes writes dominate a fast rebuild.
- A small warm append has one durable checkpoint. A worker whose final
  checkpoint already saved the result skips a duplicate final save.
- Global lineage reconciliation runs only in stages that can change lineage.
- The pool is disposed after convergence. Steady automatic and manual budgets
  remain 64 passes / 128 MiB and 512 passes / 2 GiB respectively; an unchanged
  refresh reads no usage JSONL body and writes no index.

### Stable ambiguity is not unfinished indexing

After base and required period coverage complete, unresolved duplicate-session
identity is exposed as `ambiguous-session-identity`. Both unproven local copies
remain counted and the quality warning remains visible, but the dashboard no
longer claims that I/O is still running forever. Token totals are unchanged.

### Claude #87 production incremental index

- `claudeIncrementalIndex.ts` is now the Extension Host's production Claude
  usage refresh path.
- Per-file contributions retain a verified offset and tail signature. Append
  reads only the tail; truncate, replace, move, and delete rebuild affected
  files only.
- Cross-file response identity, request-ID cardinality and missing-ID fallback,
  prompt retry handling, first-owner content UUIDs, titles, context, sessions,
  projects, branches, workflows, costliest messages, and time buckets retain
  the established full-loader results.
- Common dashboard aggregates and rows are materialized incrementally.
  Diagnostics add anonymous `bodyReads` and `aggregateMutations` only.
- The index is in memory for v2.3.0. A new Extension Host performs one cold
  build; watcher-driven updates in the same runtime are incremental. This fixes
  #87 without adding a second persisted Claude index in this release.

## Semantics and privacy invariants

- Valid Codex `last_token_usage` remains exact request attribution;
  `total_tokens` remains active context. Only missing-last records use the
  cumulative high-water fallback.
- Cached input and reasoning remain input/output subsets and are never added or
  priced twice.
- API-equivalent cost applies current official API token prices to known models;
  unknown models remain unpriced. It is not a bill or subscription charge.
- Raw Codex IDs and paths remain short-lived local worker data. Persistence
  contains only machine-salted keys and allowlisted numeric/structural metadata.
  No credential, SQLite, prompt, response, command, or tool-argument data is read.
- Claude JSONL remains read-only. No runtime dependency or Claude disk index was
  added.

## Accepted boundaries

- The Claude index is in memory in v2.3.0 and cold-builds once per Extension Host.
- The guarded Codex `session_index.jsonl` title stream remains separate from the
  zero-body-read promise for usage JSONL.
- Stable Codex identity ambiguity retains both copies and a quality warning; it
  is not an active indexing task.
- $20/$100/$200 subscription tiers are not auto-assigned. Local logs have no
  reliable account-plus-plan identity; any future mapping must be explicit and
  opt-in.
- Provider-specific visual restyling remains follow-up work; this release keeps
  the shared dashboard design system.
