# V2.3.0 Codex Beta R8 发布交接单（中文版）

更新日期：2026-08-13

## 结论

V2.3.0 的方案 B 已完成到本地安装验收阶段。Codex 不再是嵌入式的简化面板，
而是与现有 Claude 仪表板共用同一套视觉、导航、状态和设置语言的三页产品：
**概览（Overview）**、**探索（Explore）**、**优化建议（Recommendations）**。
设置是从当前主页面进入并返回的辅助页面，不是第四个主标签页。

本轮没有把 Claude 的数据模型硬套给 Codex：不估算 Codex 美元成本，不检查、分析或
保留对话正文字段，也不虚构无法从本地日志可靠获得的 Branches／Workflows。Codex 的额度只
标为日志中的“最后观测值”，不冒充实时订阅余额。

R5 另外修复了真实环境中“已启用 Codex Beta、重载后仍完全没有结果”的阻塞问题：
持久索引在一次写入后出现合法 JSON 末尾附加数据，旧版会在加载阶段永久报错，甚至无法
进入本地日志扫描。现在只对 JSON 损坏或不支持的 schema 执行原子隔离，完整保留
`.corrupt-*.json` 备份并从空索引重建；权限等其他 I/O 错误仍然失败关闭。

R6 进一步处理本机观察到的 Extension Host 能耗：后台窗口会停止 Claude／Codex
轮询与文件 watcher；同日、同时区、完整且无变化的 Codex 索引不再重算 aggregate、
coverage 或写回约 4 MB 索引；多个 VS Code Extension Host 通过同一 index-path
lease 串行刷新，原子保存也改用每次调用唯一的临时文件。

R7 已合入正式发布的 V2.2.2，并针对维护者指出的“仍像另一款嵌套插件”完成结构级
视觉统一：标题与操作区、供应商导航、主标签页的顺序现在与 Claude 页面一致；额度
改用现有摘要卡片，最近任务不再重复显示整套统计，推荐构成改用现有模型明细行。
这不是另起一套 Codex 皮肤，而是直接复用 Claude 的 header、actions、tabs、
summary、model details、composition、table、spacing 和响应式规则。

R8 又加入 Claude Today 的正式渲染参照，并继续把 Codex 的模型／effort 明细、推荐构成、
桌面和移动端 session 列表收敛到同一套组件形态。它还合入当前 `main` 的通用配额窗口
（#86）和首次回复降级韧性（#88）；旧固定模型配置只做一次性迁移，用户看到的是
Anthropic API 实际返回的模型名称。成就／社区功能只预留了无身份、无网络的本地证据
契约，未接入 UI、设置、存储、上传或排名，不影响本次 Codex Beta 的运行路径。

## V2.3.0 实际范围

### 1. 三页 Codex 体验

- **概览**：最近任务、最近 7 天、最近 30 天、全部时间；展示 processed、fresh、
  cached input、output、reasoning、趋势、构成、覆盖率、质量和最后观测额度。
- **探索**：项目、会话、模型与推理强度；支持搜索、筛选、排序、图表日期下钻、
  项目下钻、父子谱系折叠与状态恢复。
- **优化建议**：只针对用户选定范围，根据真实聚合证据显示“观测—证据—代理指标—
  条件式行动”；没有证据时不生成泛化建议。
- **设置**：供应商感知的辅助页面，可分别关闭 Codex 数据收集和本地建议；返回时保留
  原主页面。Codex watcher 默认安静等待 30 秒，也可关闭或设为 10／60／120／300 秒。
- 桌面、移动、亮色、暗色均沿用插件原有卡片、柱状图、构成图、表格、间距和
  VS Code theme token，避免形成“插件里嵌了另一个插件”的视觉割裂。

### 2. 真实 session 与项目名称

- 精确流式读取 `$CODEX_HOME/session_index.jsonl` 的 `id → thread_name` 关系；只把
  清洗后的标题保留在内存，不写入持久索引。
- root 使用最新真实标题；child 优先使用自己的真实标题。child 没有标题时，才使用
  nickname + parent／root 标题；仍无法确定时使用本地化中性名称。
- 最近任务的项目显示只从同一规范化项目的记录中选取；匿名 root 不会再阻止同项目
  child 提供真实项目名，也不会误借其他项目的名称。task key、root 标题和父子谱系保持不变。
- 标题中的绝对路径会先替换为 `[path]`。项目优先使用 Git 仓库名，否则只使用工作
  目录 basename；不会把完整路径、URL 或原始 session ID 暴露到 UI 或索引。

### 3. 数据与统计语义

- 用量记录只发现 `sessions/**/*.jsonl` 与 `archived_sessions/**/*.jsonl`；
  `session_index.jsonl` 仅用于标题关联。credential、数据库、浏览器状态、Keychain 和
  未知文件均不纳入发现范围。
- 最近 7／30 天按设置时区中的真实事件日滚动计算；覆盖未完成时明确显示 partial，
  不把部分回填冒充完整统计。
- root、child、approval-reviewer 与无法可靠分类的剩余用量分别显示；剩余量明确标为
  root／unknown-role，不再强行分配成已知角色。
- Codex 限额是日志中的最后观测快照，过期后隐藏；不是在线 billing API。
- Claude 继续保留原成本与配额语义。跨供应商比较不会相加不兼容的 cost 或 quota。

### 4. 隐私与持久索引

- 用量 JSONL 会逐行流式、临时解析，以提取白名单内的用量与结构元数据；prompt、
  response、command、tool argument 字段不会被检查或用于分析，也不会被保留或持久化。
- 持久索引只保存带机器 salt 的伪匿名 key、数字／结构聚合，以及清洗后的项目／目录、
  agent、model、effort、role、时间与质量元数据。
- 持久索引不保存原始 ID、完整路径、URL、thread title 或对话正文。
- agent nickname、model 和 effort 在解析入口与索引 load／save 两端使用同一白名单净化；
  路径、URL、控制字符、UUID 和 64 位伪匿名键都会被丢弃。危险 bucket 归入 `unknown`
  并合并 token，避免因清洗而减少总量。
- worker 支持 append tail、truncate／replace、archive move、失败保留上次可信结果、
  single-flight、取消和安全 checkpoint。
- warm refresh 的“零重读”只指未变化的 usage-record／rollout JSONL；精确标题映射文件
  `session_index.jsonl` 每次仍会流式读取，文档不再把这两类文件混为一谈。
- 损坏 JSON 与不支持的持久索引 schema 会先被原子改名为带时间戳和进程号的
  `.corrupt-*.json`，随后从本地 usage records 重新建立；不会从损坏聚合中拼接或猜测
  数据。诊断只显示 `invalid-json`／`unsupported-schema` 安全枚举，不包含路径和内容。
- 本次实际损坏索引已保留为
  `/Users/carl/Library/Application Support/Code/User/globalStorage/growthjack.claude-code-usage/codex-index-v1.corrupt-manual-20260722.json`
  （1,336,207 bytes），原活动索引位置已腾空供首次重建。该备份未删除。

### 5. 使用行为优化

- 基于所选范围识别高 effort、多 agent、自动审批审阅、重复检查代理指标、修改后检查
  和缓存行为，并给出八种 UI 语言的可粘贴约束。
- 建议由本地确定性规则从白名单聚合生成，不调用模型或网络，也不检查或使用正文字段。
- `apply_patch` 轮次、修改后工具调用等只标为结构性代理指标，不宣称它们等于实际文件
  数或能够证明因果关系。
- 这能直接回应 Codex 5.6 sol 在普通任务上容易进入多轮审阅、独立复审和 subagent
  扩张的问题：先用本地证据指出发生在哪些范围，再建议限制 effort、审阅轮次或 agent
  数量，而不是对所有用户显示同一套空泛提示。

### 6. 发布与维护门禁

- 只有当前有焦点的 VS Code 窗口保留轮询、Claude watcher、Codex watcher 和凭据
  watcher；恢复焦点时执行一次追赶刷新。后台窗口收到全局设置变化也不会立即重复扫描。
- Codex worker 在同 manifest、同 civil day、同时区且 coverage 完整时返回
  `indexChanged=false`，不 clone／重算索引，也不调用原子保存。跨日、时区变化、索引
  恢复、迁移未完成或文件变化都会绕过该快速路径。
- `${indexPath}.lock` 是原子发布的目录租约，目录内唯一的随机 token 文件只保存 PID、
  token 和时间戳，不含路径、session、project 或用量数据。跨 Extension Host 的
  load／manifest scan／update／save 被同一 lease 包围；30 分钟 stale 或已退出 PID
  可恢复，release／reaper 只能删除自己观察到的 token 文件。50 个独立进程连续三轮
  回收同一 dead owner 时最大并发均为 1。旧 R6 候选遗留的文件型 dead lock 可安全升级
  回收，live owner 保留，符号链接失败关闭。
- 原子保存从共享 `${indexPath}.tmp` 改为
  `${indexPath}.tmp-${process.pid}-${randomUUID()}`，并发保存测试不再出现 rename
  `ENOENT`，异常清理也不会删除其他调用的临时文件。
- 发布提醒只匹配当前完整版本，默认开启但可关闭；不会继续提醒旧 V2.2 内容。
- 配额显示保留通用 5 小时／每周窗口；`showScopedWeekly` 可选显示 Anthropic API
  实际命名的模型专属周额度。旧固定模型键不再出现在产品表面，仅在首次升级时迁移
  既有偏好。
- GitHub Actions 分为 Node Tests、UI Test、Release Package 三层；发布任务必须等待逻辑
  和浏览器门禁，并在 Marketplace、Open VSX 和 Release 附件之前校验 VSIX。
- Claude 文件 watcher 只刷新 Claude；Codex watcher 独立遵守自己的安静延迟，因此
  Claude 的频繁 JSONL 写入不会绕过 Codex 的 120／300 秒低 CPU 扫描选项。
- VSCE 固定为 3.9.1；包策略拒绝源码、测试、依赖、secret、内部 review 材料、异常路径、
  重复条目、错误 runtime main 和版本不一致。
- Codex 主写 commit 使用 OpenAI Codex footer 与 co-author trailer；历史贡献者 PR 的
  merge 署名保持不变。

## 已知 Beta 边界

- Codex 不显示美元成本；本地日志不能可靠支持时，不会补造 Branches／Workflows。
- 限额不是在线余额；新写入日志出现前，最后观测值可能滞后。
- 大历史第一次 backfill 仍会消耗磁盘读取，但在可取消 worker 中执行；后续只增量读取
  变化的 usage-record／rollout 文件。
- 产品在 Beta 期间沿用现有 Marketplace identity；是否改名或拆包留待采用率复盘。
- R8 是本地候选包，不等于已发布版本。真实 Linux Extension Host 长期 CPU smoke 仍
  留在 prerelease／PR 阶段执行。
