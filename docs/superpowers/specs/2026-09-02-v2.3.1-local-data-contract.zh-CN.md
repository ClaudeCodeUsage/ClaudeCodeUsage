# Claude Code Usage v2.3.1 本地数据契约

状态：v2.3.1 规范性说明。标记为 **迁移输入** 的项目描述旧版存储，只能用于迁移或清除，不是最终目标结构。

本文件是插件读取、保留、派生、展示、导出或发送数据的事实来源。任何新增持久字段，都必须在同一变更中更新本文件、英文版、迁移与清除逻辑、隐私测试和 README 隐私表。

## 1. 不可放宽的原则

1. 本文件第 6 节的所有本地数据控制都把 Claude/Codex 日志视为只读源，绝不删除或改写。另行选择启用的“会话操作”可在用户针对单个 Claude 日志完成精确模态确认后，将它移入系统回收站（可恢复）；该源文件动作不属于本清除契约。Codex 源日志始终只读。
2. 持久缓存只保存有界聚合、游标、匿名关系和最小额度观测，不复制完整会话。
3. 账号只能表示为本机稳定的 HMAC 匿名 fingerprint。禁止保存邮箱、显示名、订阅名、原始账号 ID、凭证路径或可逆身份标识。
4. 不同 fingerprint 的观测绝不合并为账号级事实。无法证明账号连续性时，观测进入隔离的未归属 epoch；内部一致的 epoch 仍可支持明确标为低可信度的“本地历史耐用度估算”，但绝不能冒充官方账号余额或虚构账号拆分。
5. 官方百分比和重置时间是观测事实；成本、总周额度、未用额度、可信度和热力图强度均为可重算派生值。
6. API key 只能进入 VS Code SecretStorage。OAuth token、cookie、API key、Authorization header 和未经筛选的 CLI 输出不得进入 configuration、globalState、Webview 状态、日志、导出或索引。
7. 远程写入必须由用户明确触发，并预览精确目标和载荷类别；禁止后台发布 GitHub 内容。
8. 每个持久对象都要有 schema 版本、有界保留期、幂等迁移、损坏处理和用户可见的清除入口。
9. API 等效成本只是按当前已知单价计算的估算，不是账单，也不是官方订阅额度承诺。

## 3. 额度观测 schema

P2 是原子写入的文档：

```ts
interface QuotaObservationStoreV2 {
  schemaVersion: 2;
  fingerprintAlgorithm: 'hmac-sha256-v1';
  observations: QuotaObservationV2[];
}

interface QuotaObservationV2 {
  schemaVersion: 2;
  provider: 'claude' | 'codex';
  accountFingerprint: string; // 本机 HMAC 或隔离的未归属 epoch
  accountAttribution: 'verified-local-signal' | 'profile-continuity' | 'unattributed';
  observedAt: number;         // Unix 毫秒
  periodType: 'five-hour' | 'seven-day' | 'provider-scoped-seven-day';
  usedFraction: number;       // 有限数，0..1
  remainingFraction: number;  // 有限数，0..1，与 usedFraction 规范化一致
  resetAt: number | null;
  source: 'claude-official-api' | 'codex-local-structured-event';
  windowId: string;           // HMAC(provider, fingerprint, period, reset identity/epoch)
  providerWindowFingerprint: string | null; // 已知 provider window ID 的 HMAC，绝不保存原值
  confidence: 'high' | 'medium' | 'low';
  captureReason: 'refresh' | 'reset-at-change' | 'window-id-change' | 'usage-drop' | 'profile-change' | 'migration';
  flags: Array<'approximate-boundary' | 'low-log-coverage' | 'low-price-coverage' | 'account-ambiguous' | 'clock-anomaly'>;
}
```

### 3.1 Fingerprint 与账号隔离

- fingerprint 采用 `HMAC(machineSalt, provider + stableLocalIdentitySignal + algorithmVersion)`；原始 identity signal 立即丢弃。
- 文件路径只能说明本机 profile，不能证明真实账号。此类观测标为 `profile-continuity`，检测到登录/profile 改变后不得继续合并。
- Codex 若没有安全稳定的账号信号，就生成随机 `unattributed` epoch，绝不能把 Codex home hash 冒充账号。窗口变化、`resetAt` 变化、明显百分比回落或显式 profile 变化都会关闭 epoch。
- 只有 fingerprint 相同且 attribution 兼容的观测才能稳健聚合。不同 `unattributed` epoch 即使 reset 时间相同也绝不合并。
- 持久化的账号、provider window 与 window HMAC 不得进入 Webview 状态或导出；宿主在渲染前必须替换为仅对本次投影有效的临时别名。

### 3.2 校验、去重和原子写入

- 拒绝非有限时间/比例、非法周期、明显未来时间和未知自由字段。
- 只有确认来源语义时才把比例规范化为 0..1，不能静默猜测任意数值。
- 去重键：规范化后的 `provider + accountFingerprint + periodType + windowId + observedAt + usedFraction + resetAt + source`。
- 短时间内语义不变的轮询可以压缩，但每个窗口必须保留首条、末条、reset 前后及异常观测。
- 在同一目录写入清洗后的临时文件，flush/close 后原子 rename 覆盖 canonical 文件；失败时旧文件保持有效。
- 损坏或未来 schema 文件使用有界诊断名隔离，原文不得进入日志；迁移验证成功前不得覆盖唯一可恢复版本。
- 当隔离文件、中断写入文件或未完成旧迁移无法安全归属时，按 provider/账号的范围清除必须拒绝修改 P2。明确确认的全部清除在同一个跨进程 lease 内安装一个合法空 canonical P2 文档，并只移除精确匹配的 P2 辅助文件后才释放 lease，避免后续 appender 被第二阶段删除误伤。

### 3.3 重置事件与派生估算

重置/窗口边界按以下优先级判断：稳定 window ID 改变、`resetAt` identity 改变、超过噪声阈值的 used fraction 回落。同一天多次重置必须分别保留。重置事件由边界观测在运行期确定性派生，不另建第二张持久事实表。有事件时间戳时按事件切分；只有日汇总时明确标记近似。

同一稳定 fingerprint/window 内，每个有效观测产生候选：

```text
candidateFullEquivalent = pricedUsedEquivalentThroughObservedAt / usedFraction
```

只接受 `0 < usedFraction <= 1`。多个候选按定价覆盖、日志/索引覆盖、边界质量、账号归属和时效做稳健聚合。展示的总额度不得低于最终确认的已用等价值。只要一个内部一致的窗口能产生有效总额，已结束和进行中的窗口都显示 `max(full - confirmedUsed, 0)`；但如果最后一次观测之后新增的日志已超过该观测推导出的候选总额，则把总额保留为低可信度下界，并暂不显示未用值，避免伪造 `$0`。未归属、边界近似、低定价覆盖或本地多登录证据仍可展示，但必须强制为低可信度，并明确称为“本地历史耐用度估算”，而非官方账号余额。真正重叠的额度系列或竞争性的映射 epoch 仍只显示已用等价值，不虚构账号拆分。

总额/未用估算不作为永久事实落盘；单价、覆盖、日志或观测变化后重新计算。

## 4. 聚合与综合热力图语义

所有日期键都使用用户配置的数据时区。“最近 30 天”定义为该时区下今天及此前 29 个自然日期。日/月/周/模型/effort/总计必须守恒；重复刷新或重建索引必须幂等。

v2.3.1 综合热力图复用 provider 日汇总，不重复扫描源日志，也不新增第二套统计缓存。

分享渲染默认使用精选 `academicViolet` 配色和分位数强度分档，避免极少数峰值把普通活跃日压成同一浅色。用户可以在 P11 中保留精选配色 ID 或经校验的自定义十六进制主色；颜色只是渲染偏好，不是用量事实。

```text
Claude processed = input + cache_creation + cache_read + output
Codex processed  = input_total + output_total
综合活动量 = Claude processed + Codex processed
```

Codex cached input 已包含在 `input_total`，reasoning 已包含在 `output_total`，都不得重复相加。综合值只表示本机活动量，不代表生产率、账单、模型能力或 provider 等价。tooltip 必须分别展示两端构成。成本只能是可选视图，并披露定价覆盖率。

Provider 日输入本身已经去重。如果分享边界仍收到同一 provider/date 的完全相同记录，则按幂等重复处理；同一 provider/date 数值冲突时必须失败关闭并阻止导出，不能求和放大。缺失自然日仅在渲染时补零，不生成持久事实。Codex 活动序列最多保留 370 个日行——完整一年加少量边界余量——并直接复用既有 provider view。

## 5. 导出、分享和网络边界

- 确定性本地 SVG 与 Markdown 片段只能包含所选日期范围、标题、规范化日聚合、provider 标签、总计和明确限制说明。
- 导出/分享必须通过隐私 canary 测试，确保不存在账号 ID/fingerprint、项目/线程名、repo 名、本地路径、prompt/log 文本或凭证。
- GitHub owner/repo/path 是目的地偏好，不是凭证；本地分享预览／导出不执行 authentication 或身份/profile 查询。只有独立的发布动作会临时使用 VS Code authentication provider 中的 GitHub 登录，请求 `public_repo`，验证仓库为公开、核实默认分支，写入前预览精确 owner/repo/branch/path 以及创建或覆盖动作，并仅在确认写入成功后保存目的地字符串。私有仓库使用本地 SVG + Markdown，不静默升级到宽泛 `repo` 权限。
- v2.3.1 的发布验证只允许 mock GitHub publish；Goal 全程不得写入真实仓库。
- AI 建议必须先给出精确请求预览，再单独点击 Send；额度跟踪不发送本地日志；价格刷新不发送用户用量。

## 6. 用户数据控制

G6 前，设置/Data 页面和命令面板应提供：

1. 查看本地数据清单：类别、非敏感位置类别、schema、近似大小/条数、最早/最新时间和可能的网络交互。
2. 清除 Codex 派生索引并重建，不触碰源日志。
3. 按 provider/account epoch 或全部清除额度历史；该操作不可恢复，但不会改变官方额度。
4. 清除当前及已知旧版建议账本，不影响外部账号。
5. 分别重置 UI 状态和分享偏好。
6. 从 SecretStorage 清除 BYOK key。
7. “清除全部插件派生数据”执行前列出精确目标；Claude/Codex 源日志和 provider 自有凭证永远排除。

不能假定卸载一定删除 VS Code global storage；README 应披露这一点，显式清除命令才是可靠删除路径。

配置清除覆盖 Global、当前 Workspace 和所有当前已打开的 Workspace Folder 作用域。
VS Code 不会暴露只属于关闭工作区的配置；这类旧值会继续留在该工作区的 settings
文件中，直到打开该工作区后再次运行清除控制（或由用户直接删除）。清单和确认界面
必须披露这一宿主限制，不能声称已清除不可见工作区。

“清除全部”只处理当前拥有的精确名称、已知退役名称和两类带版本的旧额度前缀，绝不
泛删未知/未来 `ccu.setting.*`。任何修改前先预检所有可见配置作用域；若某旧 key 已不
再向 VS Code 注册、因而不能安全更新，整个操作必须在删除 host state/secret 之前停止，
并给出精确 key 供用户手动清理。插件激活期的自有排队写入必须在删除前排空，删除后再
验证 globalState、文件族及 P2 的精确后置条件。

Webview 自有状态只有在精确白名单清除返回真实确认后才算完成。Host 会先保存一个不含
数据值的待执行客户端动作；失败、超时或面板关闭时保留该 marker，并在下次打开面板时
幂等重放；验证确认后才删除 marker。

## 7. 迁移与发版门槛

- 迁移顺序：加载并校验当前 schema；将旧额度/config 写入新临时文档；验证不变量；原子安装；最后删除旧明文或重复状态。只有成功读取 P1 且由此得到的 P2 观测均已持久追加后，才写入 P1 迁移完成标记；读取或写入失败时保留为下次激活可重试状态。
- Secret 迁移先写 SecretStorage，再清除 Global、当前 Workspace、所有已打开 Workspace Folder 和旧 globalState 中的明文值；关闭的 workspace 会在下次打开时检查。workspace-only 或相互冲突的 key 不会静默提升为一个全局 secret：插件用固定、已本地化的恢复提示停止激活，并保留可恢复明文。在用户删除或协调该受阻的旧 workspace 值之前，它仍属于普通 configuration，因而仍可能参与 Settings Sync。机器级自动迁移只接受相同候选，因此重复/并发激活保持幂等。其他失败同样保留旧值并停止，不得假装迁移成功。
- [VS Code 扩展存储官方说明](https://code.visualstudio.com/api/extension-capabilities/common-capabilities#data-storage)指出 SecretStorage 会加密且不跨设备同步；插件依赖当前 VS Code 兼容宿主的 SecretStorage 实现，而其具体底层保护方式可能因宿主而异。普通 VS Code configuration 仍可能按用户的 Settings Sync 设置同步。
- `unknown` effort 只在字段缺失或无法识别时保留；非零时展示并解释，零时隐藏；各 effort 分量必须与 provider 总计守恒。
- 测试覆盖旧/当前/未来 schema、重复观测、损坏、连续及同日重置、回落噪声、账号/profile 改变、低定价/日志覆盖、时区边界、确定性/隐私导出及清除数据不触碰源日志。
- G1、G3、G4B、G5 执行指定的只读 Claude CLI 检查点。Claude 通过不替代本地测试和主代理的验收判断。
