# v2.3.0 Codex Beta Design

**Date:** 2026-07-20
**Status:** Direction approved by the maintainer on 2026-07-20; awaiting final spec review
**Chinese review copy:** [简体中文](2026-07-20-v2.3.0-codex-beta-design.zh-CN.md)
**Foundation:** [Codex provider foundation design](2026-07-17-codex-provider-foundation-design.md)

## Goal

Ship a usable, read-only, local-first Codex Beta in v2.3.0 while preserving every existing Claude feature and result. Codex is not forced into Claude-shaped token, cost, or quota semantics; it receives provider-specific metrics that help users understand and improve Codex behavior.

The release also fixes release announcements, removes the obsolete weekly Opus option, and updates repository guidance and attribution for Codex-led development.

## Product decision

Use a provider-neutral core with provider-specific experiences:

```text
ClaudeLogAdapter ─┐
                  ├─ ProviderUsageStore ─ Claude view
CodexLogAdapter ──┘                    ├─ Codex Beta view
                                      └─ Compare view

ClaudeLimitSource ─┐
                   ├─ ProviderLimitSnapshot ─ provider-specific status
CodexLogLimitSource┘
```

Do not map Codex into `ClaudeUsageRecord`, split the Marketplace package in v2.3.0, read Codex credentials/internal databases/browser state/private APIs, or present subscription use as actual dollar spend. The product keeps the Claude Code Usage name during beta; naming or package separation waits for an adoption review.

## Release scope

v2.3.0 includes:

1. provider contracts and a Claude adapter with unchanged results;
2. a local Codex JSONL adapter, incremental index, and quality flags;
3. Claude, Codex, and Compare dashboard entry points;
4. Codex-specific token, model, effort, subagent, and structural-overhead analysis;
5. last-observed Codex limit snapshots sourced from logs;
6. provider-aware status-bar behavior and settings;
7. exact-version release announcements with a default-on opt-out;
8. removal of `showOpusWeekly` and its UI;
9. documentation, localization, tests, and Codex attribution policy updates.

Cross-device sync, OTel ingestion, Codex credential/API access, subscription cost, automatic Codex configuration changes, achievements, and product renaming are not in v2.3.0.

## Data contracts

The shared layer carries stable, explainable facts instead of one Claude-shaped snapshot:

```ts
type UsageProvider = 'claude' | 'codex';

interface NormalizedUsageEvent {
  provider: UsageProvider;
  sourceKind: 'local-jsonl';
  schemaVariant: string;
  timestamp: number;
  sessionKey: string;
  parentSessionKey?: string;
  projectKey?: string;
  model?: string;
  effort?: string;
  role?: 'root' | 'subagent' | 'approval-reviewer' | 'unknown';
  tokens: {
    inputTotal: number;
    cachedInput?: number;
    cacheWriteInput?: number;
    outputTotal: number;
    reasoningOutput?: number;
    sourceTotal?: number;
  };
  confidence: 'exact' | 'partial' | 'estimated' | 'unknown';
  qualityFlags: string[];
}

interface ProviderLimitSnapshot {
  provider: UsageProvider;
  observedAt: number;
  source: 'oauth' | 'local-log';
  windows: Array<{
    label?: string;
    usedPercent: number;
    windowMinutes?: number;
    resetsAt?: number;
  }>;
  confidence: 'exact' | 'last-observed' | 'unknown';
}
```

Raw session IDs, parent IDs, and paths may exist only in short-lived adapter memory. The persistent index uses stable pseudonymous keys derived with a machine-local salt. Diagnostics and exports never contain raw values.

## Codex source and schema

Discover only `$CODEX_HOME/sessions/**/*.jsonl` and `$CODEX_HOME/archived_sessions/**/*.jsonl`, defaulting `CODEX_HOME` to `~/.codex`. Explicitly exclude `auth.json`, SQLite/internal account databases, configuration secrets, shell history, browser/keychain state, and unknown files.

Record types observed locally on 2026-07-20 include `session_meta`, `turn_context`, `event_msg`, `response_item`, `compacted`, `world_state`, and inter-agent metadata. Treat rollout JSONL as an unstable interface guarded by schema variants, field checks, and fixtures.

## Codex token semantics

The Codex view uses:

- **Processed tokens:** source-native input + output.
- **Fresh input + output:** `max(0, input - cached_input) + output`; useful for separating new context/generation from cache replay, but not claimed to equal billable cost or quota weight.
- **Cached input:** a subset of input, never added again.
- **Reasoning output:** a subset of output, never added again.
- **Approval review:** `codex-auto-review` shown separately from user-selected Sol/Terra/Luna usage.

`total_token_usage` is a repeated cumulative snapshot and fork/subagent sessions may inherit a parent baseline. The parser therefore:

1. keeps component high-water state for each session lineage;
2. emits a delta only when a cumulative component advances;
3. uses the parent baseline for the first snapshot, or `total - last` with a quality flag when the parent cannot be resolved;
4. deduplicates archive/move copies by session and manifest identity;
5. starts a controlled new lineage for compaction, truncation, or counter regression and never turns a negative delta into silent usage;
6. attributes model/effort only when the delta can be stably associated with `turn_context`, otherwise using Unknown;
7. enforces cached-input and reasoning-output subset invariants in tests.

Unreliable lineage or schema interpretation yields `partial` or `unknown`, never invented precision.

## Incremental indexing and responsiveness

The maintainer machine currently has 545 Codex JSONL files totaling about 2.4 GB, with a largest file around 92 MB. v2.3.0 must not read that history on the Extension Host main thread or reparse it on every refresh.

Use:

- a Node worker thread for discovery, streaming parsing, and aggregation;
- a provider descriptor and single-flight scan coordinator;
- recent-file-first initial backfill;
- raw paths used only in worker memory during discovery and matched to the index through a machine-salted file key; per-file persistence contains only the pseudonymous file key, size, mtime, device/inode when available, byte offset, partial-line carry, schema variant, parser high-water, and numeric contribution;
- tail-only parsing for append-only files, rebuilding only a file whose size shrinks, identity changes, or parser state becomes incompatible;
- temp-file plus atomic rename persistence in extension global storage;
- chunking, cooperative yielding, scanned-byte/file progress, cancellation, and resumable verified partial indexes;
- explicit coverage and quality while backfill is incomplete;
- a 30-second Codex quiet debounce with 60/120/300-second and off options and no hidden shorter override;
- separate anonymous metadata-scan and parse timing for Linux CPU diagnostics.

On a warm refresh, unchanged JSONL bodies are not read. One active append reads only the new tail, and multiple watcher events coalesce into one scan.

## Dashboard and status bar

### Provider selection

The dashboard exposes Claude, Codex Beta, and Compare. Claude-only installs retain the current entry point; Codex-only installs open Codex; installs with both initially retain Claude and show a clear provider switch. Disabling Codex prevents its watcher, worker, and any network work.

### Codex view

For recent task, 7-day, 30-day, and project scopes, show processed tokens, fresh input + output, output, reasoning, cache share, root tasks, threads/subagents, Sol/Terra/Luna/auto-review, effort, task-reported duration, active time, last-observed limit state, optimization cards, and quality/coverage. Do not show Codex subscription cost or an API-equivalent estimate in v2.3.0.

### Compare

Compare places provider-native processed total, output, sessions/tasks, and active time side by side. It never sums providers, cost, or quota, and labels each provider definition.

### Status bar

Add `statusBarProvider = auto | claude | codex`. Auto preserves Claude when Claude data exists and otherwise uses Codex. Codex defaults to recent-task fresh usage, with processed/output alternatives, and may append a clearly last-observed limit. Claude and Codex quota are never mixed.

## Codex usage guidance

v2.3.0 guidance is deterministic and local. It reads no prompt/response body, calls no model, and changes no Codex setting.

### Multi-agent tax

Show a normal advisory when descendant threads are at least three and child fresh share is at least 40%; strengthen it at 70%. Always show child count, processed share, fresh share, and task duration.

### Ultra and effort comparison

Ultra tasks always show subagent shape and fresh share. For high/xhigh/max/ultra tasks that change at most three files in at most two patch rounds without an evident parallel output shape, recommend comparing the same representative task one effort level lower. Wording says “compare,” not that effort is the sole cause.

### Post-change command intensity

Count command calls after the last file change and commands per changed file. For a small change with at least five post-change calls or a ratio of at least three, flag possible repeated checking. Because command bodies are not read, label this a structural proxy rather than calling every call a test or review.

### Cache and long-context explanation

When processed/fresh is high, explain that caching reduced fresh input and do not describe all processed tokens as equivalent cost. Recommend splitting or restarting only when fresh usage, task duration, and compaction also rise.

### Approval reviewer separation

Show `codex-auto-review` as permission/tool approval overhead. Suggest checking approval policy only when its fresh share is material; never call it independent code review.

### Paste-ready constraints

Guidance cards may produce a short constraint such as:

```text
Do not start independent reviews or subagents. Run only the focused test tied
to the change, then one full test pass. Stop when the acceptance criteria pass;
do not expand this into production-grade hardening.
```

Existing AI Advice/Optimizer remains an explicit network action. It may later consume structural metrics but never automatically sends raw Codex content.

## Codex limit snapshots

A Codex `token_count` event may carry `rate_limits.primary` with `used_percent`, `window_minutes`, and `resets_at`. Store only the last observation, label it as such, clear it to unknown after its reset without a new observation, never invent a missing secondary/weekly window, never sum it across devices/providers, and never read credentials or call a network endpoint to refresh it.

## Settings and migration

Add:

- `codex.enabled`, default true but activated only when a Codex directory exists;
- `codex.dataDirectory`, empty for `CODEX_HOME`/`~/.codex` auto-detection;
- `codex.fileWatchSeconds`, default 30 with 0/10/30/60/120/300;
- `statusBarProvider`, default `auto`;
- `codex.statusMetric`, default `fresh`, alternatives `processed` and `output`;
- `releaseAnnouncements`, default true.

Remove `showOpusWeekly` from the settings catalog, config mapping, status-bar arguments, formatter options, tests, and current-feature documentation. Preserve historical changelog and contributor credit while noting retirement in v2.3.0. Leave old global-state values inert instead of destructively deleting them.

Keep generic Claude 5-hour/weekly quota. If Anthropic later exposes a stable, verified Fable 5-specific field, render the provider-returned label dynamically rather than reintroducing a hard-coded model switch.

## Release announcements

Key `WHATS_NEW` by the full release version:

```ts
const WHATS_NEW: Record<string, ReleaseAnnouncement> = {
  '2.3.0': { /* only v2.3.0 content */ }
};
```

On upgrade, look up only the current full version with no major/minor fallback. Fresh installs establish a baseline without a toast. Disabled announcements still record the seen version. Preview shows the newest defined entry, never stale 2.2 content. The v2.3.0 announcement mentions only Codex Beta, optimization guidance, exact announcements, and quota cleanup. All visible copy covers all eight UI locales.

## Privacy and security

Codex directories remain read-only. Do not read `auth.json`, internal databases, keychains, or browser state. Codex produces no default network request. The index stores only numeric contributions, a pseudonymous manifest, and pseudonymous relationship keys. Logs and diagnostics contain no prompt, response, tool arguments, command text, raw path, raw session ID, username, or credential. Structural guidance uses only record type, tool name, counts, timestamps, and patch-metadata counts; path-shaped patch keys are counted but never persisted or emitted. Content from `compacted`, `world_state`, messages, tool arguments, and command bodies does not enter usage aggregation or the index. Export and future sync do not include raw Codex data; sync remains gated by a separate privacy review.

## Errors and quality degradation

Each source returns success, partial, unavailable, or error. Quality flags include `unknown-schema-variant`, `missing-parent`, `counter-regression`, `truncated-jsonl`, `index-backfill-incomplete`, `model-effort-unattributed`, and `stale-limit-snapshot`. While `index-backfill-incomplete` is present, the UI states that current totals are incomplete, shows verified indexed-files/total-files progress, and says that indexing continues automatically.

One bad file does not erase a verified index. Retain its prior contribution as stale and rebuild it on manual retry or later change. Diagnostics report only provider, flags, counts, anonymous timing, and byte coverage.

## Test strategy

Use red-green TDD for every behavior. Fixtures are synthetic or redacted; local rollouts are never committed.

Cover:

- unchanged Claude totals/cost/quota snapshots before and after the adapter;
- Codex root, resume, archive, fork, subagent, auto-review, compaction, and truncation;
- cumulative duplicates, parent baselines, interleaved counters, and reset;
- cached-input and reasoning-output subset invariants;
- cold scan = incremental append = persisted-index reload;
- move/archive deduplication;
- malformed/future-schema quality flags;
- a 2+ GB synthetic manifest metadata path that does not read unchanged bodies;
- worker cancel/resume, single-flight, and watcher coalescing;
- exact-version announcement, disabled setting, and preview;
- complete removal of current `showOpusWeekly` surfaces;
- eight locales, seven READMEs, and bilingual AGENTS/ARCHITECTURE policy;
- diagnostics free of forbidden fields.

Run `npm run compile`, `npm test`, VSIX packaging, and an F5 smoke test. When available, install the VSIX on macOS and Linux for provider detection, warm-refresh, and CPU smoke tests.

## Acceptance criteria

v2.3.0 may become a release candidate only when:

- existing Claude tests and golden totals are unchanged;
- Codex fixture totals match source-native totals or visibly degrade;
- cached/reasoning subsets are not double-counted;
- 2.4-GB-class history does not block the Extension Host;
- warm refresh reads no unchanged JSONL body;
- the Codex view explains processed, fresh, cache, reasoning, and child share;
- last-observed limits do not impersonate live remote quota;
- guidance is evidence-backed, reversible, and content-free;
- the current release announcement is correct and optional;
- the weekly Opus switch is gone while contributor history remains credited;
- there is no credential access, default Codex network request, or sensitive diagnostic;
- compile, tests, package, and smoke tests pass.
