# v2.3.0 Codex 仪表板对齐设计

**日期：** 2026-07-20
**英文副本：** [English](2026-07-20-v2.3.0-codex-dashboard-parity-design.md)

## 目标

让 Codex Beta 看起来和用起来都属于现有插件，而不是另一套独立仪表板。在 Codex 数据能够支持相同交互的地方，直接复用 Claude 仪表板已有的导航、指标卡、柱状图、构成条、表格、设置面板、本地化和数字格式。

这里追求的是“语义对齐”，而不是牺牲准确性的表面对齐。Codex 继续不虚构美元成本，不读取对话或命令正文，也不会在本地日志无法可靠支持时制造空白的 Branches 或 Workflows 页面。

## 比较过的方案

1. **完全复制 Claude。** 一比一复制 Today、This Month、All Time、Content、Branches 和 Workflows。否决原因是其中若干数值只能缺失、受时区精度影响或被虚构。
2. **语义对齐（采用）。** 复用已建立的界面系统和设置，但使用真实的 Codex 时间范围、指标和行为诊断。
3. **独立的 Codex 分析实验室。** 保留当前独立视觉语言，只继续增加卡片。否决原因是它会保留本地测试中已经发现的突兀感。

## 导航与功能模块

Codex 使用和 Claude 相同的横向标签交互及视觉状态：

1. **最近任务**：最近一个根任务的完整 lineage，包括子线程和权限审批线程。
2. **最近 7 天**：滚动七天用量，包含按日柱状图和表格。
3. **最近 30 天**：滚动 30 天用量，包含按日柱状图和表格。
4. **全部时间**：全部已索引用量，包含按月柱状图和表格。
5. **线程**：展示 Codex 自己记录的真实线程标题；可按名称、时间、角色、项目、模型、effort、processed／fresh／output／reasoning、缓存占比和时长筛选、排序，并呈现根线程与子代理的父子关系。
6. **项目**：使用和 Claude Projects 相同的表格语言，以真实且可验证的项目名称汇总，并可下钻到该项目的线程。
7. **行为**：Codex 特有的构成分析与本地优化信号。
8. **设置**：直接在 Codex 模式中渲染现有 Settings 面板；工具栏齿轮打开此标签，不再跳回 Claude。

设计有意保留滚动 7／30 天，而不基于当前 UTC 按日聚合声称时区精确的“今天／本月”。这样可以避免把 v2.3.0 扩展成一次新的时间戳索引迁移。Content、Branches 和 Workflows 继续只属于 Claude。

## 可视化

全部可视化复用 Claude 已有的 CSS 组件和交互模式。

- 最近 7 天和 30 天按活跃日期显示柱状图及表格。
- 全部时间按月份显示柱状图及表格。
- 图表指标按钮可以切换 Processed、Fresh、Output、Reasoning 和 Threads。
- 每个时间范围都有类似 Claude“成本构成”的 **Token 构成条**：新鲜输入、缓存输入和输出是三个互不重叠的部分。Reasoning 明确标注为 output 的子集，绝不重复计入总量。
- “行为”页面提供根任务、subagent 和权限审批线程的 **线程角色构成**，并显示 effort 和模型构成。
- VS Code 主题变量、间距、指标卡、表格 hover 和响应式横向滚动继续以 Claude 页面为准。

图表不会引入新的视觉体系，也不会暗示美元成本。

## Codex 行为诊断

行为诊断继续完全在本地、以确定性规则计算，可以展示：

- subagent 新鲜 Token 占比及每个根任务的子线程数；
- 权限审批线程的新鲜 Token 占比；
- high／max／ultra effort 占比；
- processed 与 fresh 的放大比、输入缓存占比；
- reasoning 在输出中的占比；
- 修改后命令密度和 patch 轮数；
- compaction 次数，作为长上下文信号；
- 已获批准的最近任务 Codex 建议。

建议只描述相关性和结构性代理指标，不声称因果关系。插件不会读取或显示 prompt、response、command、tool argument、原始路径、session ID、credential 或私有数据库内容。

## 设置对齐

- Codex 模式渲染 provider-aware Settings 面板，不再重定向到 Claude，也不在 Codex 页面混入不会生效的 Claude-only 设置。
- 现有共享设置在语义成立时应用到 Codex：语言、紧凑 Token 数、Token 小数位、版本提醒、仪表板自动刷新、供应商选择、Codex 状态栏指标、Codex home 和 Codex watcher 延迟。
- 新增 `codex.optimization.enabled`，默认开启；它只控制“行为／优化”页面的显示，不关闭 Codex 数据收集。
- Claude 专属设置仍可在共享面板中访问，但不会被静默解释为 Codex 设置。
- 不为 Codex 增加 credential、订阅成本、自动修改配置或读取会话正文的设置。

## 数据与渲染边界

- 使用现有数字化按日聚合增加“全部时间”范围和按月数据。
- 保留有上限的最近线程列表，并明确显示“已显示／总数”。
- 把现有 `I18n.formatNumber` 传给 Codex 渲染器，使紧凑数字偏好与 Claude 一致。
- 把已由插件内部渲染的 Codex Settings HTML 传给 Codex 渲染器；它是可信的扩展输出，不是日志正文。
- 所有动态值继续进行 HTML escaping；不显示完整路径、原始 session ID 或仓库 URL。
- 索引允许增加向后兼容的可选身份字段，但不得为此重新解析 2.4 GB 全历史。旧索引通过只读取每个 rollout 开头的 `session_meta` 做一次有界身份补全。

## 真实 Session 与项目身份

真实名称优先于匿名编号，来源和降级顺序固定如下：

- 根 Session 标题来自 Codex 本地 `session_index.jsonl` 的最新 `id → thread_name` 记录。这是 Codex 自己维护的标题索引，不扫描 prompt／response 正文；标题只在内存中与匿名 session key 关联，不写入插件持久化索引。
- 子代理优先使用其线程标题；没有标题时使用 `session_meta.agent_nickname`，并显示父 Session 标题。不得显示 `Thread 1`、`Thread 2` 一类伪装成名称的顺序编号。
- Git 项目优先从 `session_meta.git.repository_url` 提取仓库名；本地目录 basename 仅作为辅助标签。非 Git 项目使用 `cwd` basename。
- 项目分组 key 仍为加盐 HMAC：Git 项目对仓库 URL 做 HMAC，非 Git 项目对 `cwd` 做 HMAC。索引只保存安全显示名和匿名 key，不保存完整路径或 URL。
- 元数据确实缺失时，UI 明确显示“未命名 Session”或“未识别项目”，并保留角色、时间等可验证信息，不从提示词、文件名或 session ID 猜名称。

## Codex 额度窗口

- 每个 `limit_id` 保留最后观测快照，展示其 `limit_name`、primary／secondary 窗口、重置时间、观测时间和可用的 credits 状态。
- 状态栏继续使用一个简洁的最近窗口；详情页显示全部仍有效的已观测窗口，并明确标注“最后观测”，不声称是实时 API 值。

## 旧 Webview 与测试包

此前 VSIX 实际已正确安装，但已打开的 Webview 会保留旧 HTML，直到 VS Code 窗口重新加载。因此本轮交接必须：

- 使用独立的 `codex-beta-r2` VSIX 文件名；
- 验证安装包包含新版标签 marker；
- 明确要求同版本本地安装后执行 `Developer: Reload Window`；
- 内部发布版本继续使用 `2.3.0`，避免本地测试扭曲版本提醒行为。

## 测试与验收

- 范围聚合测试覆盖全部时间和按月数据，确保 token 子集不被重复计算。
- 构成测试证明“新鲜输入 + 缓存输入 + 输出 = processed”，reasoning 不会重复相加。
- 行为测试覆盖零分母、角色占比、effort 占比和不完整时间戳。
- 渲染测试要求八个 Codex 标签、Claude 视觉类、图表、Settings 内容、本地化文案、紧凑数字格式，并禁止原始标识和美元成本。
- Webview 测试要求 Codex 齿轮打开 Codex Settings，并独立恢复 Codex 标签状态。
- TypeScript 与全仓库测试保持通过。
- 最终 VSIX 检查内部版本、新 bundle marker、禁止文件，并在复制到项目根目录后核对 SHA-256。
