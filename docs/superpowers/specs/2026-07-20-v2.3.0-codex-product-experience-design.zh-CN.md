# v2.3.0 Codex 产品化体验设计

**日期：** 2026-07-20

**状态：** 已批准——用户选择方案 B，并授权设计完成后直接实施

**英文副本：** [English](2026-07-20-v2.3.0-codex-product-experience-design.md)

## 决策摘要

v2.3.0 不再把 Codex Beta 做成八个平铺标签的独立分析页，而是把它重组为与现有 Claude 仪表板同属一个产品的三段式体验：

1. **概览**：先回答“还能否继续使用、最近消耗了多少、趋势怎样”。
2. **探索**：再回答“用量去了哪个项目、任务、Session、模型或 effort”。
3. **优化建议**：最后回答“哪些行为值得调整，以及证据是什么”。

Claude 页面保持现有信息架构，避免在 v2.3.0 引入不必要的回归；Codex 复用 Claude 已成熟的组件、间距、色彩、表格和洞察卡，而不是只借用同名 CSS 类。设置从 Codex 主导航移到右上角，作为辅助页面保留。

## 已比较方案

- **方案 A：保留八标签精修。** 改动较小，但时间范围和功能模块仍混在同一层级，无法根治产品结构问题。
- **方案 B：Codex 产品化重构（采用）。** 只重组 Codex，完整复用 Claude 设计语言，同时保留供应商特性，收益与风险最平衡。
- **方案 C：双供应商统一重构。** 长期复用最高，但会同时改动成熟 Claude 页面，v2.3.0 回归面过大。

## 背景与已确认问题

当前 Codex Beta 已具备真实 Session／项目名称、范围聚合、额度、模型、effort、角色和本地行为信号，但界面仍像一套嵌入现有插件的独立原型：

- 最近任务、7 天、30 天、全部、线程、项目、行为、设置八个标签全部平铺，时间范围与功能模块处于同一层级。
- 图表按钮复用 `.chart-tab`，却没有复用 Claude 图表的事件契约；点击后会继续冒泡到全局 Claude handler，可能以空 metric 再更新一次图表。
- 图表、构成条和明细表被渲染为相邻但割裂的模块，缺少“标题 → 范围 → 指标 → 图表 → 构成 → 明细”的完整叙事。
- 项目展开按钮、数字列、建议卡等只借用了局部样式，语义和交互并未与 Claude 组件一致。
- Webview 整体重绘后只恢复少量 Codex 状态；搜索、筛选、排序、图表指标和展开状态会丢失。
- 额度只强调已用百分比，窗口名称、剩余量、重置时区、数据新鲜度和“非实时”属性不够清楚。
- 建议区在缺少相应证据时仍可能生成通用的测试或停止条件，无法做到真正的证据驱动。
- Session 表格列数过多，窄窗口只能依赖横向滚动；标签、排序、筛选和展开操作的键盘及 ARIA 支持不足。
- 当前“最近 7／30 天”先按 Session 最后活动时间选中整个文件，再计入该 Session 的全部历史 Token；它不是严格的期间用量。日/月桶和时间显示也固定使用 UTC，没有遵循插件配置时区。
- 当前 `filesChanged` 实际是 `apply_patch` 调用次数，`commands` 实际是其他 tool call 次数；这些结构代理量不能显示成精确修改文件数、命令数或复审轮数。

## 目标

- 让 Codex Beta 第一眼就属于 Claude Code Usage，而不是另一款嵌套插件。
- 优先支持三项用户决策：查看额度、定位高用量来源、形成可执行的行为约束。
- 保留 Codex 独有信息，包括 processed／fresh、缓存复用、reasoning、effort、subagent 和 approval reviewer。
- 保证 Session 和项目名称来自真实元数据；缺失时明确降级，不猜测名称。
- 让 7／30 天范围只计算配置时区内落入对应自然日的事件，不再按 Session 最后活动时间纳入完整历史。
- 在刷新、切换供应商和 Webview 重绘后保留用户当前探索状态。
- 在 360、480 和 1280 像素宽度下保持可读，页面本身不产生横向溢出。
- 建立足以阻止交互回归的自动化门禁，而不仅是 HTML 字符串断言。

## 非目标与永久边界

- 不估算或显示 Codex 美元成本。
- 不提取、分析、持久化或展示 prompt、response、command body、tool argument 等正文。索引器仍需逐行扫描 JSONL 并解析事件外壳，但只选择允许的用量、身份和结构元数据。
- 不制造本地日志无法可靠统计的 Branches、Workflows 或对话内容标签。
- 不把 reasoning 重复计入总 Token；它始终是 output 的子集。
- 不把本地日志中的最后观测额度称为实时 API 额度。
- 不在本轮重构 Claude 页面，也不为了视觉对称而削弱 Codex 的真实语义。
- 不自动修改 Codex 配置、模型或 effort；插件只给出可选建议。

## 术语与统计语义

界面固定使用以下术语，避免 Task、Session、Thread 混用：

| 术语 | 定义 | UI 用法 |
|---|---|---|
| 任务（Task） | 一个根 Session 及其全部子代理／审批 Session 的 lineage | “最近任务”、任务级汇总 |
| Session | 一条可验证的本地 Codex 运行记录，可为根、subagent 或 approval reviewer | 探索表格和筛选 |
| 项目（Project） | 从 Git 仓库或本地工作目录元数据派生的匿名分组与安全显示名 | 项目汇总和下钻 |
| Processed | 日志报告的总处理 Token | 主用量规模 |
| Fresh | 新鲜输入加输出，不包含缓存输入 | 新增模型负担的近似量 |
| Cached input | 被复用的输入 Token | 缓存复用情况 |
| Reasoning | 输出 Token 的子集 | 只作输出构成，不重复求和 |

Session 时长如果仍为各记录报告值的求和，必须标为“Session 时长累计”，不得称为任务墙钟时长。建议和比较必须同时标注其时间范围。

7 天定义为配置时区下“今天及前 6 个自然日”，30 天定义为“今天及前 29 个自然日”。期间总量只累加时间范围内的事件切片；不能把最近活跃 Session 的完整历史算入期间总量。

## 全局外壳

### Provider-aware 标题

- Claude 模式继续显示现有标题和操作。
- Codex 模式标题显示“Codex 使用量”与低调的 “Beta” 标记。
- 标题下方显示索引更新时间、覆盖状态和“本地日志 · 非实时”说明，不使用夸张的 Beta 视觉。
- Codex 右上角只保留“刷新”和“设置”；不会显示只对 Claude 生效的 AI 建议入口。
- Provider 切换仍位于标题下方，并补齐 `tablist`、`tab`、`aria-selected` 和键盘语义。

### Codex 主导航

主导航固定为三个入口：

- **概览**
- **探索**
- **优化建议**（受现有 `codex.optimization.enabled` 控制）

“设置”不再占主标签。点击右上角设置进入 Codex provider-aware 设置页，并提供返回上一个 Codex 主页面的入口。关闭优化建议后，概览与探索的本地数据仍正常工作。

## 概览设计

概览遵循由紧急到解释的顺序。

### 1. 额度状态

额度卡位于概览最上方，并展示全部仍有效的最后观测窗口：

- 使用人类可读名称，例如“5 小时窗口”“每周窗口”，不直接暴露 `primary`、`secondary` 或 `300m`。
- 同时显示“已用 42% · 剩余 58%”，进度条仍使用插件现有颜色体系。
- 重置时间同时显示配置时区下的绝对时间和相对倒计时。
- 明确显示最后观测时间以及“来自本地日志，并非实时查询”。
- 无额度快照、快照已过期、credits unlimited 和真正的 0% 使用必须具有不同文案。

### 2. 最近任务

最近任务使用一张横向信息卡显示：

- 真实任务标题；没有真实标题时显示“未命名任务”。
- 真实项目名称和可选的安全目录 basename。
- 最后活动时间、根 Session 数、子 Session 数和 approval reviewer 数。
- Processed、Fresh、Output、缓存占比和 Session 时长累计。
- “在探索中查看”操作，跳转到已带任务／项目过滤条件的 Session 视图。

### 3. 用量趋势

趋势模块是一块完整的 Claude 风格区段，而不是图表和表格两个相邻卡片：

1. 区段标题和范围分段控件：最近任务、7 天、30 天、全部。
2. 摘要指标：Processed、Fresh、Output、缓存占比、任务／Session 数。
3. 指标切换：Processed、Fresh、Output、Reasoning、Session。
4. 柱状图。
5. Token 构成条：新鲜输入、缓存输入、输出；Reasoning 单独标明为 output 子集。
6. 按日或按月明细表。

最近任务没有适合的时间序列时，只显示任务摘要与构成，不绘制没有意义的单柱趋势图。7 天和 30 天补齐范围内的空日期；全部时间按月。图表标签根据宽度降低密度，图表区域可以局部滚动，但页面主体不得横向溢出。

点击或用键盘激活日期／月份柱，跳转到“探索 → Session”，并带入对应时间过滤条件。

## 探索设计

探索页使用二级分段控件，而不是增加新的主标签：

- **项目**（默认）
- **Session**
- **模型与 effort**

### 项目视图

- 默认按最近活动排序，展示真实项目名称、最后活动、Processed、Fresh、Output、根任务、子 Session 和审批 Session。
- 项目代表名称选择最新的非空真实名称；仅当候选名称都存在时才优先根 Session，避免匿名根记录覆盖有名称的子记录。
- 展开项目时显示最近 Session，并明确“显示 20／总数”。
- “查看全部 Session”切换到 Session 视图并设置项目过滤条件。
- 展开按钮使用现有 disclosure 视觉，但采用真正的 button reset、可访问名称和 `aria-expanded`。

### Session 视图

- 搜索真实标题；可按角色、项目、模型、effort、时间范围过滤。
- 默认树形显示根 Session 和全部递归后代。
- 存在搜索或筛选时改为扁平结果，并保留“父任务”列，避免匹配子 Session 因父项被隐藏而消失。
- 折叠根 Session 时递归折叠全部后代，而不只处理直接子项。
- 显示过滤 chip、清除全部和可朗读的结果计数；无结果时提供单一明确的重置操作。
- 宽屏表格的数字列右对齐、等宽且不换行；窄屏仅保留名称、角色、项目、Fresh 和时间，其余信息在行内 details 中展示。

### 模型与 effort 视图

- 使用与 Claude Model Details 一致的 section header、构成条和表格。
- 模型与 effort 可以按最近任务、7 天、30 天、全部切换。
- 指标必须标注作用域；不得把 all-time 数据放在看似 recent 的页面中。

## 优化建议设计

优化建议页由“行为构成、证据、条件式行动”三部分组成，可切最近任务、7 天、30 天和全部时间。

### 行为构成

- 根 Session、subagent 和 approval reviewer 的 Fresh 构成。
- 模型与 effort 构成。
- Processed／Fresh 放大比、缓存占比、reasoning 输出占比、每根任务子 Session 数、patch 调用数、compaction 和 patch 后工具调用代理量。
- 这些指标均标为本地结构代理量，不声称因果关系。

角色只表示日志父链和已知 metadata 的结构分类；不能把 subagent 自动称为独立审阅，也不能把 approval reviewer 占比直接称为“开销”。`apply_patch` 次数不能称为修改文件数，其他 function call 次数不能称为命令数或测试轮数。

### 建议卡契约

每张建议卡必须包含：

1. **观察**：哪个范围内出现了什么信号。
2. **证据**：使用可读标签和格式化数值，不显示内部 evidence key。
3. **解释**：说明它为何可能增加用量，并明确这是相关性或代理指标。
4. **条件式行动**：只有任务类型允许时才建议降低 effort、限制 subagent 或缩短复审链。

没有达到阈值的信号不生成建议。没有建议时显示“当前范围未发现强信号”，而不是自动追加“跑一次完整测试”或“停止生产级加固”等通用约束。Paste-ready constraint 仅由当前已触发信号组成；不会建议跳过确有必要的安全、测试或审阅步骤。

### 数据质量

覆盖率、索引文件／字节数、质量 flag 和刷新时间放在页尾折叠区，但任何会影响当前数字解释的 partial coverage 必须同时靠近对应数字显示。

## 视觉系统

- 继续使用 VS Code theme token，不引入独立品牌背景、渐变或新的卡片体系。
- 完整复用 Claude 的 `section-header`、`usage-summary`、`summary-grid`、`cost-composition`、`daily-breakdown`、`daily-table`、`insight-card`、`table-hint` 和 Session 控件契约。
- Codex 专属类只负责布局和语义修饰，不重新定义一套颜色、阴影或按钮。
- 减少 `.model-item` 的无差别堆叠：只有可展开实体使用实体卡；主内容用区段和留白建立层级。
- Beta 标记为小型中性色 pill，不成为页面视觉中心。
- 数字使用现有紧凑格式设置；百分比和时长使用本地化单位，不泄漏 `m`、`h`、`files`、`bytes` 等英文片段。

## 状态与交互架构

新增版本化的 `CodexUiState`，至少保存：

- 主页面；
- 概览时间范围和图表指标；
- 探索二级页面；
- Session 搜索、筛选、排序和方向；
- 展开的项目与任务；
- 优化建议时间范围；
- 设置页返回位置。

状态通过 `acquireVsCodeApi().getState()/setState()` 保存，并对旧值进行白名单校验。Webview 刷新或 provider 数据更新后恢复同一探索上下文；如果目标项目／Session 已不存在，则安全降级并显示结果为空，而不是抛错。

Codex 交互使用限定在 `.codex-view` 内的单一事件委托：

- 不再依赖 inline `onclick`。
- `data-codex-action` 明确动作和参数。
- Codex handler 完成处理后阻止继续进入 Claude 图表 handler。
- Claude 全局图表 handler 也显式忽略 `.codex-view` 内事件，并拒绝空 metric。

这既修复当前图表双重处理，也建立可测试的供应商边界。

## 响应式与可访问性

### 响应式验收

- 1280px：完整表格和并列模块。
- 480px：导航、范围和筛选控件换行；摘要卡两列或自适应。
- 360px：摘要卡单列；Session 使用紧凑列加 details；页面主体无横向滚动。
- 表格或图表自身允许局部横向滚动，但必须有视觉提示，不能把整个页面撑宽。

### 可访问性验收

- Provider、主导航和二级导航具有正确的 tablist／tab／tabpanel、`aria-selected` 和键盘方向键行为。
- 指标和范围分段按钮使用 `aria-pressed` 或等价 tab 语义。
- 排序控件可通过 Enter／Space 操作，并维护 `aria-sort`。
- 搜索具有可见或屏幕阅读器 label；结果计数使用 `aria-live="polite"`。
- 展开按钮有目标名称和 `aria-expanded`。
- 图表提供文本摘要；颜色不是区分数据的唯一手段。
- HTML `lang` 跟随当前 locale。

## 实现边界

- `codexView.ts` 负责语义 HTML 组合，拆分为概览、探索、建议和辅助设置渲染函数。
- 新增纯 `CodexUiState` 模块，负责默认值、白名单恢复和状态转换，便于无 DOM 单元测试。
- Codex 客户端交互从 `webview.ts` 的巨大通用脚本中收敛为独立、可测试的安装函数或脚本生成器。
- `webview.ts` 继续负责共享外壳、provider 切换和 Claude 页面，但 Claude 与 Codex 的事件边界必须明确。
- provider/index 层只为真实名称选择、日期下钻或可靠统计补充必要字段；不得无预算地一次性重扫全部历史，也不得扩大正文提取范围。
- 不新增 runtime dependency。UI 门禁使用 `@playwright/test` 与 `@axe-core/playwright` devDependency；它们不得进入 VSIX 运行包。

## 时间范围与索引迁移

为了纠正现有期间统计，索引增加版本化的本地日切片，至少保存每日本地时区下的 Token、模型、effort 和结构代理汇总。Session 角色和项目身份继续由安全元数据关联，原始 session ID、完整路径和仓库 URL 不进入索引。

- 索引记录生成日切片时使用的 IANA 时区或固定 UTC offset；设置时区变化时触发重新切片。
- 旧索引的 all-time 总量继续可用，不因迁移而清零。
- 迁移优先最近文件，并按每轮字节／文件预算在 worker 中分批执行；每个文件之间主动 yield，可取消、可续跑，不在一次刷新中无上限扫描全部历史。
- 迁移未完成时，受影响的期间范围显示“部分覆盖”，并禁止从不完整范围生成确定性优化建议；不得回退到“活跃 Session 全历史”冒充精确期间数据。
- 后台迁移进度进入 coverage 模型，用户可看见最近范围和全部历史分别完成到什么程度。

身份数据同时做以下准确性加固：常见 SSH／HTTPS／`.git` 仓库 URL 规范化后再分组；标题按有效 `updated_at` 选择最新记录；项目代表名称使用最新非空真实名称；任务最后活动时间取整个 lineage 最大值；active 与 archived 中明显重复的同一匿名 Session 去重，无法判定时标记 partial。

## 测试与质量门禁

实施遵循测试先行：先写失败测试，再完成最小实现。

### 数据与渲染测试

- 三个主页面、三个探索子页面和辅助设置路由存在，旧八主标签不再出现。
- 真实 Session／项目名称及缺失降级正确；原始路径、URL、session ID、正文和美元成本永不渲染。
- 项目名称选择不会让匿名根记录覆盖有名称的子记录。
- SSH／HTTPS 仓库 URL 变体归入同一项目；同名但不同仓库保留安全的次级区分。
- Session title 索引按 `updated_at` 而非偶然文件行序取最新；active/archive 重复记录不会静默双算。
- 额度窗口的人类标签、已用／剩余、配置时区、倒计时、最后观测与不同空状态正确。
- 建议严格由对应 evidence 触发；无 evidence 时没有通用 paste constraint。
- Token 构成保持互斥，reasoning 不重复计数。
- 跨日、DST 和非整小时 UTC offset 下，7／30 天只累加范围内日切片；迁移未完成时明确为 partial。
- UI 与文案禁止把 patch/tool call 代理值称为文件数、命令数、测试轮数、复审次数或因果性开销。

## 发布策略

- 本次作为 v2.3.0 Codex Beta 的质量提升继续完成，不拆成一个粗糙的 v2.3.0 再补丁修复。
- Beta 表示数据源兼容性和统计语义仍可能随 Codex 日志演进，不代表界面可以缺少基本产品质量。
- Claude 现有页面通过回归测试后保持不变。
- 若方案 B 在一至两个版本中验证稳定，再考虑后续版本把 Claude 与 Codex 的共享外壳进一步抽象；本轮不执行方案 C。

## 完成定义

只有同时满足以下条件才视为完成：

1. Codex 只有“概览／探索／优化建议”三个主页面，设置为辅助页面。
2. 额度、最近任务、趋势、来源探索和建议形成清晰决策路径。
3. 图表双重事件、状态丢失、名称选择、空状态和窄屏问题得到测试覆盖。
4. 建议是证据驱动的，并遵守隐私和统计边界。
5. 中文和英文视觉 QA 通过，Claude 页面无回归。
6. Node 与 Playwright release gate 通过，并生成可在项目目录中直接安装的 R4 VSIX。
