# v2.3.0 Codex Beta 设计

**日期：** 2026-07-20
**状态：** 维护者已于 2026-07-20 批准设计方向；等待本 spec 最终复核
**英文副本：** [English](2026-07-20-v2.3.0-codex-beta-design.md)
**基础设计：** [Codex Provider 基础设计](2026-07-17-codex-provider-foundation-design.zh-CN.md)

## 目标

v2.3.0 直接交付可用、只读、本地优先的 Codex Beta，同时保持现有 Claude 功能和统计结果。Codex 不被强制塞入 Claude 的 token、成本或配额结构；它使用能够帮助用户理解和优化 Codex 行为的 provider-specific 指标。

本版本同时修复版本提醒，删除过时的每周 Opus 限制选项，并更新 Codex 接手开发所需的仓库规则与署名约定。

## 产品决策

采用 provider-neutral core + provider-specific experience：

```text
ClaudeLogAdapter ─┐
                  ├─ ProviderUsageStore ─ Claude view
CodexLogAdapter ──┘                    ├─ Codex Beta view
                                      └─ Compare view

ClaudeLimitSource ─┐
                   ├─ ProviderLimitSnapshot ─ provider-specific status
CodexLogLimitSource┘
```

不采用以下方案：

- 不把 Codex 字段直接映射到 `ClaudeUsageRecord`；
- 不在 v2.3.0 拆成两个 Marketplace 扩展；
- 不读取 Codex credential、内部数据库、浏览器状态或私有 API；
- 不把订阅用量显示为实际美元支出。

Beta 期间产品名称保持 Claude Code Usage。是否改为中性名称或拆分扩展，由 Codex adoption review 决定。

## 发布范围

v2.3.0 包含：

1. provider contract 与保持 Claude 结果不变的 Claude adapter；
2. Codex 本地 JSONL adapter、增量索引和 quality flags；
3. Claude、Codex、Compare dashboard 入口；
4. Codex 特有用量、模型／effort／subagent／结构性开销分析；
5. 从日志读取的 last-observed Codex limit snapshot；
6. provider-aware 状态栏与设置；
7. 精确版本提醒和默认开启的关闭开关；
8. 删除 `showOpusWeekly` 及其 UI；
9. 文档、本地化、测试和 Codex 贡献署名规则更新。

不在 v2.3.0 实现：跨设备同步、OTel 摄取、Codex credential/API 调用、订阅成本、自动修改 Codex 配置、成就系统或产品改名。

## 数据契约

内部不再要求所有 provider 共享一个 Claude-shaped snapshot。公共层只承载稳定、可解释的事实：

```ts
type UsageProvider = 'claude' | 'codex';

interface NormalizedUsageEvent {
  provider: UsageProvider;
  sourceKind: 'local-jsonl';
  schemaVariant: string;
  timestamp: number;
  sessionKey: string;
  parentSessionKey?: string;
  projectKey?: string;
  model?: string;
  effort?: string;
  role?: 'root' | 'subagent' | 'approval-reviewer' | 'unknown';
  tokens: {
    inputTotal: number;
    cachedInput?: number;
    cacheWriteInput?: number;
    outputTotal: number;
    reasoningOutput?: number;
    sourceTotal?: number;
  };
  confidence: 'exact' | 'partial' | 'estimated' | 'unknown';
  qualityFlags: string[];
}

interface ProviderLimitSnapshot {
  provider: UsageProvider;
  observedAt: number;
  source: 'oauth' | 'local-log';
  windows: Array<{
    label?: string;
    usedPercent: number;
    windowMinutes?: number;
    resetsAt?: number;
  }>;
  confidence: 'exact' | 'last-observed' | 'unknown';
}
```

Raw session ID、parent ID 和 path 只允许在 adapter 的短生命周期内存中出现。持久化索引使用本机 salt 生成的稳定伪匿名 key；任何诊断或导出都不得包含 raw value。

## Codex 数据源与 schema

默认只发现：

- `$CODEX_HOME/sessions/**/*.jsonl`；
- `$CODEX_HOME/archived_sessions/**/*.jsonl`；
- 当 `CODEX_HOME` 未设置时使用 `~/.codex`。

明确排除 `auth.json`、SQLite／内部账户数据库、config secret、shell history、浏览器／keychain 状态和其他未知文件。

2026-07-20 本地观测到的记录类型包括 `session_meta`、`turn_context`、`event_msg`、`response_item`、`compacted`、`world_state` 和 inter-agent metadata。rollout 是不稳定接口；adapter 必须用 schema variant、字段守卫和 fixture 管理变更。

## Codex token 语义

Codex 页面使用以下指标：

- **Processed tokens**：source-native input + output；用于表达模型处理过的总上下文和生成量。
- **Fresh input + output**：`max(0, input - cached_input) + output`；用于区分新增上下文／生成与缓存重放，但不声称等价于账单或 quota 权重。
- **Cached input**：input 的子集，不与 input 再次相加。
- **Reasoning output**：output 的子集，不与 output 再次相加。
- **Approval review**：`codex-auto-review` 单列，不混入用户选择的 Sol／Terra／Luna 主模型解释。

`total_token_usage` 是重复出现的累计快照，fork／subagent 可能继承 parent baseline。解析规则为：

1. 每个 session lineage 维护 component high-water；
2. 只有累计值前进时才产生 delta；
3. 首个 snapshot 使用 parent baseline，或在无法解析 parent 时使用 `total - last` 并标记 quality flag；
4. archive／move 通过 session identity 和 manifest identity 去重；
5. compaction／truncation／counter regression 开启新 lineage，绝不把负 delta 静默变成 usage；
6. model／effort 归因只应用到能够和 `turn_context` 稳定关联的 delta；无法关联的 token 放入 Unknown；
7. cached-input 和 reasoning-output 通过 invariant 测试保证不重复计算。

当 lineage 或 schema 无法可靠解释时，provider total 显示 `partial` 或 `unknown`，而不是虚构精确值。

## 增量索引与响应性

本机实测 Codex 日志为 545 个 JSONL、约 2.4 GB、最大单文件约 92 MB。v2.3.0 不允许在 Extension Host 主线程全量读取，也不允许每次刷新重新解析全历史。

实现采用：

- Node worker thread 执行发现、streaming parse 和聚合；
- provider descriptor + single-flight scan coordinator；
- 最近修改文件优先的首次 backfill；
- 每次发现时仅在 worker 内存中使用 raw path，并以本机 salt 生成的 file key 匹配索引；每个文件只持久化 pseudonymous file key、size、mtime、可用时的 device/inode、byte offset、partial-line carry、schema variant、parser high-water 和数字贡献；
- append-only 文件从上次 offset 继续；size 变小、identity 改变或 parser state 不兼容时只重建受影响文件；
- index 以 temp + atomic rename 写入扩展 global storage；
- worker 分块并主动 yield，报告 scanned bytes/files 和 indexing progress；取消后保留已验证的 partial index；
- dashboard 在 backfill 未完成时明确显示 coverage 和 quality，不把 partial total 当 all-time exact；
- file watcher 只触发 30 秒 quiet debounce，Codex 可选 60／120／300 秒或关闭；不存在隐藏的短间隔覆盖；
- metadata scan 和 parse 分开记录匿名耗时，便于 Linux CPU 回归诊断。

Warm refresh 验收目标：未变化时不读取 JSONL 正文；单个活动文件追加时只读取新增尾部；多个 watcher event 合并为一次 scan。

## Dashboard 与状态栏

### Provider 选择

dashboard 提供 Claude、Codex Beta、Compare：

- 只有 Claude 数据时保持现有 Claude 入口；
- 只有 Codex 数据时默认 Codex；
- 两者都有时首次仍显示 Claude，并明确展示 provider switch；
- Codex 可以关闭；关闭后不启动 watcher／worker，也不发网络请求。

### Codex 页面

首版显示最近任务、7 天、30 天和项目范围：

- Processed tokens、Fresh input + output、output 和 reasoning；
- cache share；
- root task、thread、subagent 数量；
- Sol／Terra／Luna／auto-review 与 effort 分布；
- task-reported duration 和 active time；
- last-observed limit window；
- usage optimization cards 和 quality／coverage 状态。

不显示 Codex subscription cost。API-equivalent estimate 不进入 v2.3.0。

### Compare

Compare 只并列展示 provider-native processed total、output、sessions／tasks 和 active time。不同 provider 不求和；每列显示自身定义，cost 和 quota 永不进入 Compare total。

### 状态栏

新增 `statusBarProvider = auto | claude | codex`：

- `auto`：有 Claude 数据时保持 Claude；否则使用 Codex；
- Codex 默认显示 recent-task fresh usage；用户可改为 processed 或 output；
- 可用时附加 last-observed limit，注明 stale／observed 状态；
- 不在状态栏混合 Claude 和 Codex quota。

## Codex 使用优化建议

v2.3.0 首先提供完全本地、确定性的建议。规则不读取 prompt／response 正文，不调用外部模型，也不自动改 Codex 设置。

### Multi-agent tax

- descendant thread ≥3 且 child fresh share ≥40%：显示一般提醒；
- child fresh share ≥70%：显示强提醒；
- 展示 child count、processed share、fresh share 和 task duration，不只给抽象判断。

### Ultra／effort 对照

- ultra 任务始终显示 subagent 结构与 fresh share；
- high／xhigh／max／ultra 且任务仅修改 ≤3 文件、patch round ≤2、无明显并行产物时，建议用同一代表性任务比较低一档；
- 文案使用“建议比较”，不声称 effort 是 token 上升的唯一原因。

### Post-change command intensity

统计最后一次文件修改后的命令调用数和每个 changed file 的命令数。小改动后 ≥5 次命令，或命令／文件比例 ≥3 时，提示可能存在重复检查。由于不读取命令正文，UI 必须标为结构性 proxy，不能全部称为测试或审阅。

### Cache 与长上下文解释

processed／fresh 比值较高时，同时告诉用户缓存已减轻 fresh input；不得把全部 processed token 描述为等价成本。若 fresh usage、task duration 和 compaction 同时升高，再建议拆分长任务或开启新 task。

### Approval-reviewer 分离

`codex-auto-review` 单列为权限／工具审批开销。只有其 fresh share 明显时才提示检查 approval policy；不得称为独立代码审阅。

### 可复制约束

建议卡可生成短的 paste-ready 约束，例如：

```text
不要启动独立审阅或 subagent。只运行与改动直接相关的聚焦测试，
然后运行一次完整测试；达到验收条件后停止，不扩展到生产级加固。
```

现有 AI Advice／Optimizer 仍是用户显式触发的网络功能；后续可消费这些结构化指标，但不得自动发送原始 Codex 内容。

## Codex limit snapshot

Codex `token_count` event 可能包含 `rate_limits.primary`：`used_percent`、`window_minutes`、`resets_at`。adapter 只记录最后观测快照：

- UI 使用 “last observed” 文案并显示观测时间；
- 在 `resets_at` 之后没有新观测时清空为 unknown；
- 缺少 secondary window 时不伪造 weekly；
- snapshot 不跨设备或 provider 求和；
- 不为获得更新而读取 credential 或发起网络请求。

## 设置与迁移

新增设置：

- `codex.enabled`：默认 true，但只有检测到 Codex 目录时才启动；
- `codex.dataDirectory`：空值自动使用 `CODEX_HOME`／`~/.codex`；
- `codex.fileWatchSeconds`：默认 30，支持 0／10／30／60／120／300；
- `statusBarProvider`：默认 `auto`；
- `codex.statusMetric`：默认 `fresh`，可选 `processed`／`output`；
- `releaseAnnouncements`：默认 true。

删除 `showOpusWeekly` 的 catalog、config mapping、status-bar 参数、formatter option、测试和当前功能文档。历史 changelog／贡献者 credit 继续保留，并注明该功能在 v2.3.0 退休。旧 globalState 值保持 inert，不需要破坏性删除。

通用 Claude 5h／weekly quota 保留。若 Anthropic 将来提供稳定且可验证的 Fable 5 专属字段，使用 provider-returned label 动态展示，不重新引入写死模型名称的开关。

## 版本提醒

`WHATS_NEW` 改为完整版本键：

```ts
const WHATS_NEW: Record<string, ReleaseAnnouncement> = {
  '2.3.0': { /* only v2.3.0 content */ }
};
```

规则：

- upgrade 时只查当前完整版本，不回退到旧 major.minor；
- fresh install 仍只建立 baseline，不弹窗；
- `releaseAnnouncements=false` 时记录已见版本但不显示；
- preview 命令显示当前最新定义，不再错误显示 2.2；
- v2.3.0 文案只描述 v2.3.0：Codex Beta、优化建议、精确提醒和配额清理；
- 所有用户可见文本覆盖八个 UI locale。

## 隐私与安全

- 对 Codex 目录 read-only；不修改 rollout；
- 不读取 `auth.json`、internal DB、keychain 或浏览器状态；
- 默认零 Codex 网络请求；
- 索引只保存数字贡献、relative manifest 和伪匿名关系键；
- 日志和诊断不得包含 prompt、response、tool arguments、command text、raw path、raw session ID、username 或 credential；
- optimization proxy 只使用 record type、tool name、数量、时间和 patch metadata 计数；path-shaped patch key 只计数，不持久化或输出；
- `compacted`、`world_state`、message、tool arguments 和 command body 的内容不进入用量聚合或索引；
- share card／export／未来 sync 默认不包含 Codex raw data；任何同步仍推迟到单独 privacy review。

## 错误处理和质量降级

每个 source 返回 outcome：success、partial、unavailable 或 error。常见 quality flag 包括：

- `unknown-schema-variant`；
- `missing-parent`；
- `counter-regression`；
- `truncated-jsonl`；
- `index-backfill-incomplete`；
- `model-effort-unattributed`；
- `stale-limit-snapshot`。

出现 `index-backfill-incomplete` 时，UI 必须说明当前总量不完整、索引会自动继续，并显示已验证的
已处理文件数／总文件数；基础索引与期间覆盖全部收敛后自动移除该提示。

单个坏文件不清空已验证索引；保留旧 contribution 并标 stale，用户手动重试或文件再次变化后重建。诊断只报告 provider、flag、计数、匿名耗时和 byte coverage。

## 测试策略

所有行为按 red-green TDD 实施。fixture 使用合成／脱敏数据，不提交本地 rollout。

必须覆盖：

- Claude adapter 前后 totals／cost／quota snapshot 完全一致；
- Codex root、resume、archive、fork、subagent、auto-review、compaction、truncation；
- cumulative duplicate、parent baseline、interleaved counter 和 reset；
- cached-input／reasoning-output subset invariants；
- cold scan = incremental append = persisted-index reload；
- move/archive 不重复计算；
- malformed／future schema quality flags；
- 2+ GB synthetic manifest 的 metadata path 不读取 unchanged body；
- worker cancel／resume、single-flight 和 watcher coalescing；
- exact-version notification、disabled setting 和 preview；
- `showOpusWeekly` 不再出现在设置、config、UI 或 README 当前功能中；
- 八 locale、七 README、AGENTS／ARCHITECTURE bilingual policy；
- diagnostics 不含禁止字段。

完整验证：`npm run compile`、`npm test`、VSIX package、F5 smoke test；条件允许时在 macOS 与 Linux 安装 VSIX 做 provider detection、warm refresh 和 CPU smoke test。

## 验收标准

v2.3.0 Codex Beta 可以进入 release candidate，当且仅当：

- Claude 现有测试和 golden totals 不变；
- Codex fixture source-native totals 一致，或明确降级；
- cached／reasoning 不重复计算；
- 2.4 GB 等级历史不会阻塞 Extension Host；
- warm refresh 不读取 unchanged JSONL body；
- Codex 页面能解释 processed、fresh、cache、reasoning 和 child share；
- last-observed limit 不冒充 live remote quota；
- insights 只给证据化、可撤销建议，不读取正文；
- 当前版本提醒正确且可关闭；
- Opus weekly 开关已移除但贡献者历史 credit 保留；
- 无 credential access、无默认 Codex 网络请求、无敏感诊断；
- compile、tests、package 和 smoke test 通过。

## 后续版本

- v2.3.x：根据真实 schema drift 和用户反馈修正 Codex Beta，不扩大权限；
- v2.4：provider-neutral 本地成就／习惯趋势，需单独设计；
- v2.4.x：在 consent、删除、retention 和安全评审后，预览 GitHub 认证的 opt-in 聚合同步；
- adoption review：决定产品命名、是否拆分扩展及 API-equivalent estimate 是否值得加入。
