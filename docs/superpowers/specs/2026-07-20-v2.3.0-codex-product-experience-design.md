# v2.3.0 Codex Product Experience Design

**Date:** 2026-07-20

**Status:** Approved — the user selected Option B and authorized implementation after design

**Primary review copy:** [简体中文](2026-07-20-v2.3.0-codex-product-experience-design.zh-CN.md)

## Decision

Codex Beta will move from eight flat tabs to three product-level destinations: **Overview**, **Explore**, and **Recommendations**. Settings becomes an auxiliary provider-aware page opened from the header. Claude keeps its current information architecture for v2.3.0, while Codex adopts the complete component and interaction contracts of the existing dashboard rather than borrowing isolated class names.

The experience must first answer whether the user can continue, then where usage went, and finally what behavior may be worth changing.

## Alternatives considered

- **Polish the existing eight tabs:** lower change risk, but preserves the mixed time/function hierarchy and cannot solve the product-structure problem.
- **Codex product redesign (selected):** restructures Codex only, adopts the complete Claude design language, and preserves provider-specific semantics.
- **Unified two-provider redesign:** strongest long-term reuse, but unnecessarily puts the mature Claude dashboard at risk in v2.3.0.

## Goals

- Make Codex feel native to Claude Code Usage while preserving truthful Codex-specific semantics.
- Prioritize limits, usage attribution, and evidence-backed behavior guidance.
- Preserve verified task, session, and project names with explicit unnamed fallbacks.
- Persist navigation, scope, chart, filtering, sorting, and disclosure state across redraws.
- Work at 360, 480, and 1280 pixel widths without page-level horizontal overflow.
- Add an interaction-level quality gate beyond HTML string assertions.
- Make 7/30-day totals include only event slices within configured-timezone calendar days instead of entire histories of recently active sessions.

## Non-goals and permanent boundaries

- No inferred Codex dollar cost.
- No extraction, analysis, persistence, or display of prompt, response, command-body, tool-argument, or other conversation content. The indexer still scans JSONL lines and parses event envelopes, but selects only allowed usage, identity, and structural metadata.
- No invented Branches, Workflows, or content-analysis modules.
- Reasoning remains an output subset and is never double-counted.
- Last-observed local-log limits are never described as live API values.
- Claude is not structurally redesigned in this release.
- The extension never changes Codex model, effort, or configuration automatically.

## Terminology

| Term | Meaning |
|---|---|
| Task | One root session and its full subagent and approval-reviewer lineage |
| Session | One verified local Codex run record |
| Project | An anonymized grouping with a safe display name derived from repository or working-directory metadata |
| Processed | Total processed tokens reported by the log |
| Fresh | Fresh input plus output, excluding cached input |
| Cached input | Reused input tokens |
| Reasoning | A subset of output tokens |

Summed per-record duration is labeled **Cumulative session duration**, never task wall-clock duration. Every recommendation and comparison names its active scope.

Seven days means today plus the previous six calendar days in the configured timezone; 30 days means today plus the previous 29. Period totals accumulate only event slices in that range, never complete histories selected by last session activity.

## Provider-aware shell

- Codex shows a “Codex Usage” title with a restrained Beta badge, index freshness, coverage state, and “local logs · not live” disclosure.
- Codex header actions are Refresh and Settings; Claude-only advice is not shown.
- Provider and Codex navigation use complete tablist/tab/tabpanel semantics and keyboard behavior.
- Codex primary navigation contains Overview, Explore, and Recommendations only.
- Settings opens as an auxiliary Codex-aware page and returns to the previous primary destination.

## Overview

### Usage limits

- Show all valid last-observed windows with human names such as 5-hour and weekly.
- Show both used and remaining percentages.
- Show reset time in the configured timezone plus a relative countdown.
- Show observation time and explicitly label the source as local-log, not live.
- Distinguish missing, expired, unlimited-credit, and genuine zero-usage states.

### Recent task

Show the verified title, verified project, optional safe directory basename, last activity, root/child/approval session counts, Processed, Fresh, Output, cache share, and cumulative session duration. A “View in Explore” action opens the relevant filtered session view.

### Usage trend

One cohesive Claude-style section contains scope selection (recent task, 7 days, 30 days, all time), summary metrics, metric selection, chart, mutually exclusive token composition, and daily/monthly detail table. Recent task omits a meaningless one-bar time series. Empty dates are filled for 7/30-day scopes; all-time is monthly. Chart activation drills into filtered sessions.

## Explore

Explore has secondary destinations: **Projects** (default), **Sessions**, and **Models & effort**.

### Projects

- Sort by recent activity by default.
- Use the newest verified non-empty project name; prefer a root name only when both candidates are named.
- Expanded rows state “showing 20 of total” and provide “View all sessions”.
- Disclosure controls use the existing visual language with correct button reset and accessible naming.

### Sessions

- Search verified titles and filter by role, project, model, effort, and time scope.
- Show recursive lineage when unfiltered.
- Switch to flat filtered results with a Parent task column when filters are active.
- Recursively collapse descendants.
- Show filter chips, Clear all, an aria-live count, and a single useful no-results action.
- Use right-aligned, monospaced, non-wrapping numeric cells on wide screens; use key columns plus per-row details on narrow screens.

### Models & effort

Reuse the existing Model Details section, composition, and table language. Every model and effort breakdown exposes its scope.

## Recommendations

The page combines role/model/effort composition, structural behavior metrics, and evidence-backed conditional actions. It supports recent task, 7-day, 30-day, and all-time scopes.

Roles describe parent-chain and known metadata structure only; a subagent is not automatically an independent review. Apply-patch call counts are not file counts, other function calls are not command/test/review counts, and approval-reviewer share is not automatically overhead.

Every recommendation contains an observation, readable evidence, a proxy/correlation interpretation, and a conditional action. Signals below threshold render no card. With no triggered evidence, the page says no strong signal was found and does not append generic testing or hardening constraints. Paste-ready constraints are composed only from active signals and never recommend skipping necessary review, safety, or testing.

Coverage and quality diagnostics live in a collapsed footer, while partial coverage warnings also appear next to affected values.

## Visual system

- Use VS Code theme tokens and the existing dashboard spacing, typography, tables, summaries, compositions, and insight cards.
- Codex-specific classes modify layout or semantics only; they do not create a second card/color/shadow system.
- Reduce generic `.model-item` stacking and use sections and whitespace for hierarchy.
- Keep the Beta badge neutral and secondary.
- Localize number, percent, duration, file, and byte units.

## State and event architecture

A versioned `CodexUiState` persists the primary page, overview scope and metric, Explore destination, search/filters/sort, expanded projects/tasks, recommendation scope, and Settings return destination through the VS Code webview state API. Restored values are allow-listed and safely degrade when their target data no longer exists.

Codex uses one event-delegation boundary rooted at `.codex-view`, with `data-codex-action` instead of inline handlers. The Codex handler prevents handled events from entering Claude chart code. The Claude handler also explicitly ignores `.codex-view` and rejects an empty metric.

## Responsive and accessible behavior

- 1280px shows full tables and side-by-side sections.
- 480px wraps navigation, scopes, filters, and summary cards.
- 360px uses one-column summaries and compact session rows with details.
- Tables and charts may scroll locally; the page body may not overflow horizontally.
- Tabs expose correct ARIA state and keyboard arrows; metric controls expose pressed/selected state.
- Sorting supports Enter/Space and updates `aria-sort`.
- Search has a label, result counts are polite live regions, disclosures are named, and charts have text summaries.
- The HTML `lang` follows the current locale.

## Implementation boundaries

- Refactor `codexView.ts` into semantic render functions for Overview, Explore, Recommendations, and auxiliary Settings.
- Add a pure, versioned `CodexUiState` module for validation and transitions.
- Extract Codex client behavior from the generic `webview.ts` script into an independently testable installer or script generator.
- Keep `webview.ts` responsible for the shared shell/provider switch and make Claude/Codex event boundaries explicit.
- Add provider/index fields only when required for truthful names or drill-downs; never rescan conversation bodies or all historical token data for a visual refactor.
- Add no runtime dependency. The UI gate uses `@playwright/test` and `@axe-core/playwright` as devDependencies only; they stay out of the VSIX runtime package.

## Period accuracy and index migration

The index gains versioned configured-timezone daily slices for tokens, model, effort, and structural proxies. Raw session IDs, full paths, and repository URLs remain excluded.

- The index records the IANA timezone or fixed UTC offset used for slicing; changing it triggers re-slicing.
- Existing all-time totals remain available during migration.
- Migration prioritizes recent files and runs in bounded file/byte batches in the worker, yielding between files and supporting cancellation/resume instead of rescanning unlimited history in one refresh.
- Incomplete period slices render a visible partial-coverage state and cannot produce deterministic recommendations. The UI never falls back to a whole-session approximation while labeling it exact period usage.
- Coverage reports recent-period and historical migration progress separately.

Identity accuracy is also tightened: normalize common SSH/HTTPS/`.git` repository URL variants before grouping; select titles by valid `updated_at`; choose the newest non-empty verified project name; use lineage-max last activity; deduplicate obvious active/archive copies and mark ambiguous cases partial.

## Quality gate

- Rendering tests cover the three primary pages, three Explore destinations, auxiliary Settings, naming fallbacks, limit states, evidence-triggered advice, mutually exclusive token composition, and privacy boundaries.
- Period tests cover cross-midnight, DST, and non-hour UTC offsets, proving 7/30-day ranges include only in-range slices and expose partial migration state.
- Identity tests cover SSH/HTTPS repository variants, out-of-order title updates, unnamed roots with named children, and active/archive duplicates.
- State tests cover serialization, allow-list restoration, navigation, scope, metric, filtering, sorting, and disclosure state.
- Interaction tests prove Codex chart controls update once without invoking Claude chart logic; drill-downs, recursive collapse, filtering, keyboard operation, and ARIA state work.
- A static full-Webview Playwright harness loads production-rendered HTML, CSS, and script with an `acquireVsCodeApi` stub rather than duplicating a test page.
- Axe reports zero serious/critical violations; explicit keyboard tests cover tabs, sorting, disclosures, and segmented controls.
- Six stable screenshot baselines cover the three desktop-light primary pages, desktop-dark Overview, and 360px mobile Overview and Sessions. Fixtures, locale, timezone, time, fonts, and animation state are fixed.
- All eight locales run page-level overflow checks at 360×800 and 1280×900; tables and charts may only overflow inside their own containers. English and Simplified Chinese receive manual checks for Overview, Sessions, Recommendations, and Settings, with a 480×900 smoke breakpoint.
- TypeScript, all Node tests, repository policy tests, and `git diff --check` pass.
- The R4 VSIX is copied to the project root, checked for version, bundle marker, forbidden files, and SHA-256, then tested after `Developer: Reload Window` against real local Codex metadata without reading conversation content.

## Completion criteria

The work is complete only when Codex has the three-destination product flow, limits and usage attribution are clear, recommendations are evidence-driven, interaction/state/name/responsive regressions are covered, Claude remains stable, and a verified R4 VSIX is ready in the project directory.
