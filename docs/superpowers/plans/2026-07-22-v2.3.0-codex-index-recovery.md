# V2.3.0 Codex Index Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 V2.3.0 在持久 Codex 索引损坏或 schema 不受支持时保留原文件、自动从空索引重建，并生成可安装的 R5。

**Architecture:** `loadCodexIndex` 仍是唯一索引读取边界；它只隔离内容级错误，其他 I/O 错误继续上抛。恢复原因通过可选回调进入 worker result、provider diagnostic 和安全日志，不携带路径或原始内容。现有有界 worker 负责重建，不增加同步扫描。

**Tech Stack:** TypeScript 5.8、Node.js 20、`node:test`、worker_threads、Playwright 1.61.1、VSCE 3.9.1。

## Global Constraints

- 只恢复 `invalid-json` 与 `unsupported-schema`；ENOENT 保持空索引，其他 I/O 错误上抛。
- 损坏索引只能原子改名为同目录 `.corrupt-<epoch>-<pid>.json`，不得删除或修改内容。
- 诊断不得包含路径、解析片段、session ID、标题或对话字段。
- 不新增 runtime dependency，不改变源码 `package.json`／lock 根版本 `2.1.1`。
- 主要代码提交必须包含 OpenAI Codex footer 与 co-author trailer。
- 只生成本地 R5；不 push、不创建 PR、不发布、不自动安装。

- [ ] **Step 3: 实现最小恢复边界**

```ts
export type CodexIndexRecoveryReason = 'invalid-json' | 'unsupported-schema';
export interface CodexIndexRecovery { reason: CodexIndexRecoveryReason; }

async function quarantineCodexIndex(indexPath: string): Promise<void> {
  const parsed = path.parse(indexPath);
  const backup = path.join(
    parsed.dir,
    `${parsed.name}.corrupt-${Date.now()}-${process.pid}${parsed.ext}`,
  );
  await rename(indexPath, backup);
}
```

`loadCodexIndex` 将 `JSON.parse` 与 schema 判断分开：`SyntaxError` → `invalid-json`；显式 schema 错误 → `unsupported-schema`。两者先 `await quarantineCodexIndex`，再回调并返回 `createEmptyCodexIndex(timeZone)`；其他错误维持原行为。
