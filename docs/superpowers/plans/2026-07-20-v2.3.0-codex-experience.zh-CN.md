# v2.3.0 Codex Beta 体验实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 将已验证的 Codex provider snapshot 接入 provider-aware dashboard、状态栏和本地用量建议，并完成八 locale、七 README 与 release candidate 验证。

**架构：** `CodexProvider` 是 extension 的唯一数据入口；纯 `codexUsage`/`codexInsights` 模块形成 UI-ready view model；纯 `codexView` 渲染独立 HTML；`webview.ts` 只负责 provider tabs 和消息路由。Claude 现有视图保持原实现，Compare 只并列兼容指标。

**技术栈：** TypeScript、VS Code Extension API、现有 dependency-free HTML/CSS webview、`node:test`、provider/index 核心计划产物，无新增 runtime dependency。

## 全局约束

- Codex 和 Claude 可以采用不同指标，不伪造成本或 quota 对等。
- Codex view 显示 processed、fresh、cache、output、reasoning、model、effort、root/child、coverage 和 quality。
- Compare 不求和 provider，不包含 cost/quota。
- 本地洞察不读取 prompt、response、command body 或 tool arguments。
- `codex-auto-review` 与独立代码审阅严格区分。
- 只有 Claude 数据时 UI/状态栏保持现状；Codex-only 自动使用 Codex；两者都有时默认 Claude。
- Codex watcher 默认 quiet debounce 30 秒，可选 0/10/30/60/120/300。
- 每个用户可见字符串覆盖八 locale；七 README 同步。
- 现有 Claude 功能、tests、share/export/advice/conversation 不回归。
- 每个任务 red-green TDD 和独立提交。
