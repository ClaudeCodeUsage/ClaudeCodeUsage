# v2.3.0 Provider 与增量索引核心实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 建立不改变 Claude 结果的 provider contract，并实现可在 2.4-GB-class Codex 历史上后台运行、可续传、可质量降级的本地增量索引。

**架构：** 纯 parser 负责 schema guard、cumulative high-water 和 provider facts；index 负责文件 manifest、append offset、持久化贡献与 coverage；worker client 把 discovery/parse 移出 Extension Host。Claude adapter 只是现有 loader 的兼容封装，先用 golden tests 锁定结果。

**技术栈：** TypeScript 5.8、Node.js `fs`／`readline`／`worker_threads`／`crypto`、`node:test`，无新增 runtime dependency。

## 全局约束

- 仅发现 `$CODEX_HOME/sessions/**/*.jsonl` 与 `$CODEX_HOME/archived_sessions/**/*.jsonl`。
- 不读取 `auth.json`、SQLite、config secret、keychain、浏览器状态或未知文件。
- Raw path/session/parent ID 只在 worker 短生命周期内存；持久化使用 machine-salted key。
- `cached_input` 是 input 子集；reasoning 是 output 子集；不得重复相加。
- `total_token_usage` 按 lineage/high-water 解析，禁止逐行累计 `last_token_usage`。
- Unknown schema/parent/counter 显式产生 quality flag。
- Unchanged warm refresh 不读取 JSONL body；append 只读取新增 tail。
- Worker 可取消、可续传、single-flight；不存在隐藏的快速轮询。
- 测试 fixture 合成生成，绝不提交真实 Codex rollout 内容。
- 每个任务 red-green TDD 和独立提交。

export type UsageProvider = 'claude' | 'codex';
export type ProviderConfidence = 'exact' | 'partial' | 'estimated' | 'unknown';
export type ProviderSourceOutcome = 'success' | 'partial' | 'unavailable' | 'error';

export interface ProviderTokenCounts {
  inputTotal: number;
  cachedInput?: number;
  cacheWriteInput?: number;
  outputTotal: number;
  reasoningOutput?: number;
  sourceTotal?: number;
}

export interface NormalizedUsageEvent {
  provider: UsageProvider;
  sourceKind: 'local-jsonl';
  schemaVariant: string;
  timestamp: number;
  sessionKey: string;
  parentSessionKey?: string;
  projectKey?: string;
  model?: string;
  effort?: string;
  role?: 'root' | 'subagent' | 'approval-reviewer' | 'unknown';

  confidence: ProviderConfidence;
  qualityFlags: string[];
}

export interface ProviderLimitSnapshot {
  provider: UsageProvider;
  observedAt: number;
  source: 'oauth' | 'local-log';
  windows: Array<{ label?: string; usedPercent: number; windowMinutes?: number; resetsAt?: number }>;
  confidence: 'exact' | 'last-observed' | 'unknown';
}

export const processedTokens = (t: ProviderTokenCounts): number =>
  Math.max(0, t.inputTotal) + Math.max(0, t.outputTotal);

export const freshInputPlusOutput = (t: ProviderTokenCounts): number =>
  Math.max(0, t.inputTotal - Math.max(0, t.cachedInput ?? 0)) + Math.max(0, t.outputTotal);

`refresh` request 可在 extension 与本地 worker 之间传递扫描根目录和索引路径；这些值不持久化到 contribution，也不出现在 worker 返回的 progress/result/error 或 diagnostics 中。返回 message 不包含 raw path/session ID，worker 内部 error 先转换为匿名 code/count。

worker 使用 `parentPort`，按最近 mtime 排序，固定 byte chunk 后 `setImmediate` yield，并在 chunk 边界检查 cancel。client 的 worker URL 为 `path.join(__dirname, 'codexIndexWorker.js')`，只允许一个 active promise。
