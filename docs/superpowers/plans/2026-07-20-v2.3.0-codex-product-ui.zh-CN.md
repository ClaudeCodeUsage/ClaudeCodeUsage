# v2.3.0 Codex 产品化界面实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Codex Beta 重构为“概览／探索／优化建议”三段式产品体验，完整采用现有插件视觉语言，并保证真实名称、证据型建议、状态恢复、响应式和可访问性。

**Architecture:** `codexView.ts` 保持公共 façade；语义 HTML 拆到 `codexViewComponents.ts`，CSS 拆到 `codexViewStyles.ts`，root-scoped 客户端控制器拆到 `codexViewClient.ts`，纯状态白名单放入 `codexUiState.ts`。`webview.ts` 只组合 provider-aware 外壳，并显式隔离 Claude/Codex 事件。所有动态数据在 extension host 端转义并渲染，不把正文或原始标识传给客户端。

**Tech Stack:** TypeScript 5.8、Node `node:test`、VS Code Webview HTML/CSS/JavaScript、VS Code theme tokens；无新增 runtime dependency。

**Prerequisite:** 先完成同批 period-accuracy plan 的 v2 安全扫描、真实日切片和 per-range coverage；本计划直接消费该契约，不再实现第二套范围聚合或全局 completion flag。

## Global Constraints

- Codex 只有“概览／探索／优化建议”三个主页面；设置是右上角打开的辅助页面。
- Claude 页面信息架构保持不变。
- 不显示美元成本，不提取／分析／持久化／展示对话正文或 tool arguments，不制造 Branches／Workflows。
- Session 和项目名称只用已验证元数据；缺失时显示明确 fallback，不从内容或 ID 猜测。
- Reasoning 明示为 output 子集，不重复计数。
- 所有结构指标使用“代理／启发式”中性命名，不声称因果关系。
- 无 evidence 时不生成建议或固定 paste-ready constraint。
- 所有 Codex 交互限定在 `[data-codex-root]`，不使用 inline `onclick`，不得进入 Claude chart handler。
- Webview state 使用 `acquireVsCodeApi().getState()/setState()`；刷新后恢复有效状态。
- 360px 页面主体不得横向溢出；表格和图表只允许容器内部滚动。
- 八个 locale 同步；README 若修改则同步仓库中当时实际存在的全部语言版本，不写死文件数量。
- 每个行为先写失败测试，再实现；每个任务独立 commit 并带 Codex co-author/footer。
