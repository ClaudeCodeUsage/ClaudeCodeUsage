# v2.3.0 Codex 期间精度、索引迁移与身份加固实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 Codex 的 7／30 天数据只统计配置时区内的真实事件日切片，在不丢失既有 all-time 总量的前提下把 v1 索引有界迁移为 v2，并加固 Session、任务与项目身份的准确性。

**Architecture:** v2 索引继续使用现有 `codex-index-v1.json` 文件路径，通过内部 `schemaVersion: 2` 原地升级，避免现有 all-time 历史失联。v2 contribution 只持久化已验证行边界的数字 offset、伪匿名身份和数值聚合；字节级 JSONL 扫描器绝不持久化未完成行。新文件和 append 在一次 parse 中同时更新 all-time 与目标时区 period；旧文件由 worker 按最近优先、32 MiB 与 16 file-pass 双预算渐进回填，并以 7 天、30 天、全部历史三套 coverage 明确暴露完成度。

**Tech Stack:** TypeScript 5.8、Node `node:test`、Node worker_threads、`Intl.DateTimeFormat`、现有原生 JSONL 索引；不新增 runtime dependency。

## Global Constraints

- 不估算或显示 Codex 美元成本。
- 不提取、分析、持久化或展示 prompt、response、command body、tool argument 等正文。
- 原始 Session ID、完整路径、repository URL、credential、原始 JSONL 行和未完成 JSONL 行不得进入 v2 索引、view model、diagnostic 或 DOM。
- Codex 发现范围保持 `$CODEX_HOME/sessions/**/*.jsonl` 与 `$CODEX_HOME/archived_sessions/**/*.jsonl`；不得扩大到 `auth.json`、SQLite、配置 secret 或未知文件。
- 7 天等于配置时区下今天及前 6 个自然日；30 天等于今天及前 29 个自然日。
- Reasoning 是 output 子集，不重复计入 processed。
- v1 已验证 all-time 总量在迁移期间保持可用；旧 UTC `byDay` 不得冒充目标时区的准确期间数据。
- 迁移必须最近文件优先、可取消、可续跑，并在每个 256 KiB chunk 后更新安全 cursor、报告 progress、yield 和检查取消；atomic checkpoint 发生在完成文件、预算结束或取消退出前。
- 单轮主索引与 period migration 共用最多 32 MiB body read 和 16 次 file pass；不能以迁移为由无预算重扫全部历史。
- 期间覆盖不完整时必须标为 partial，并不得从对应范围生成确定性优化建议。
- active/archive 只对证据完全一致的同一伪匿名 Session 自动去重；存在差异时全部保留并标为 partial。
- 结构代理字段固定为 `patchCalls`、`toolCalls`、`postPatchToolCalls`、`compactCount`、`taskCompleteCount`；不得称为修改文件数、命令数、测试轮数或复审次数。

### Safe JSONL scanner

```ts
// src/providers/codex/codexJsonlScanner.ts
export const CODEX_JSONL_CHUNK_BYTES = 256 * 1024;
export const CODEX_MAX_JSONL_LINE_BYTES = 1024 * 1024;

export interface CodexJsonlCursor {
  offset: number;
  discardingOversizedLine: boolean;
}

export interface CodexJsonlReader {
  read(
    entry: CodexRuntimeManifestEntry,
    start: number,
    endExclusive: number,
  ): AsyncIterable<Buffer>;
}

export interface CodexJsonlScanResult {
  cursor: CodexJsonlCursor;
  bytesRead: number;
  reachedEnd: boolean;
  oversizedLines: number;
}

export interface CodexJsonlChunkProgress {
  cursor: CodexJsonlCursor;
  bytesRead: number;
}

export async function scanCodexJsonlLines(
  entry: CodexRuntimeManifestEntry,
  reader: CodexJsonlReader,
  cursor: CodexJsonlCursor,
  endExclusive: number,
  onLine: (line: string, endOffset: number) => void,
  onChunk?: (progress: CodexJsonlChunkProgress) => Promise<void>,
): Promise<CodexJsonlScanResult>;
```

Scanner invariants:

- `offset` 永远指向最后一个已消费换行符之后的 byte position。
- 普通未完成行只存在于当前调用内存，函数返回前丢弃；下轮从该行起点重读。
- 单行超过 1 MiB 时进入 `discardingOversizedLine`，后续只推进数值 offset，直到发现换行；不保存被丢弃字节。
- Buffer 层先定位 `0x0a`，完整行才执行 UTF-8 decode，避免中文字符跨 chunk 被破坏。
- `onLine` 只在完整、未超长的行上调用。
- 默认 reader 的 `highWaterMark` 固定 256 KiB；scanner 在一次调用内可跨多个 chunk 保留最多 1 MiB 的短生命周期行 buffer。每个 chunk 后调用 `onChunk`，但 callback 只看到安全 cursor 和数字读取量。

## Bounded migration algorithm

1. `loadCodexIndex(indexPath, timeZone)` 同时识别 schema 1 和 schema 2；不存在时返回空 v2。
2. 读取 v1 contribution 后计算：

```ts
const verifiedOffset = Math.max(
  0,
  old.offset - Buffer.byteLength(old.carry ?? '', 'utf8'),
);
```

3. 复制 v1 的 verified all-time total、byModel、byEffort、session、parser high-water、limits 和质量 flag；执行结构字段映射。随后立即丢弃旧未完成行内容，v2 对象和下一次 atomic save 都不包含该字段。
4. 旧 UTC `byDay` 不复制到 v2 period；all-time aggregate 原值保持。
5. contribution 暂缺的 `sourceArea` 在 manifest reconciliation 时由匹配的 runtime entry 补齐；随后持久化安全 enum。
6. manifest diff 依次处理 move、remove、truncate、replace、append 和 add；待处理 entry 统一按 `mtimeMs` 降序、`fileKey` 升序排列。
7. 主索引未追平的 contribution 即使 manifest fingerprint 未变化，也重新加入工作队列；新增／append／truncate／replace 优先于 period migration。
8. 主索引与 period migration 共用单轮 32 MiB／16 file-pass budget。每个 stream chunk 最多 256 KiB；scanner 的 `endExclusive` 不超过剩余总 budget，因此整轮读取量不得超过 32 MiB。
9. 新 contribution 从 byte 0 开始，同时构建 all-time aggregate 和目标时区 period；append 在 period 的 `timeZone` 与 `indexedThrough` 均和主索引一致时，同一次 parser output 同步更新两者，不二次读取。
10. 旧 contribution 没有目标时区 period 时创建独立 `periodMigration`，从 byte 0 使用全新 parser state 重扫；迁移草稿不修改 verified all-time aggregate。
11. 每个 chunk 完成后更新 contribution 的安全 cursor，执行 progress callback、`setImmediate` yield 和取消检查。每个完成文件后、预算用尽返回前以及收到取消准备抛错前，重算 aggregate／coverage 并执行 atomic checkpoint；避免每 256 KiB 都 fsync。
12. period migration 追到 contribution 的 verified `offset` 后才原子提升为 `aggregate.period`，随后删除 migration state。未完成草稿不参与准确期间总量。
13. 时区变化时立即停止使用旧时区 period，保留 all-time，建立新时区 migration。
14. 7／30 天 coverage 的候选文件为 `endedAt` 未知或目标时区结束日不早于窗口起点的 canonical contribution；旧文件不会阻塞已准确覆盖的近期范围。all-time coverage 包含全部 canonical contribution。
15. exact duplicate 从 aggregate、period totals 和文件 view 中排除；ambiguous group 全部保留，identity coverage 为 partial。
16. cancellation 在 chunk 边界先保存当前安全 cursor，再抛出取消错误，因此人工取消不丢失已验证进度。若 chunk 处于未完成行中，安全 cursor 仍停在该行起点，下轮会重读该行但不会持久化内容。Worker 异常终止最多重做当前未 checkpoint 的一个 file pass，仍受 32 MiB 单轮上限约束。
